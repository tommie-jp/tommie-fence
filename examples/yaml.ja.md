# YAML の書き方

[English](yaml.md) | [日本語](yaml.ja.md)

tommie-fence のフェンスは、中身を YAML で書きます。9 つのフェンスで書き方は共通です。
ここでは、フェンスを読む・直すのに要る分だけを説明します。各フェンスのキー
(`parts:` `wires:` など) の意味は、それぞれのパッケージの README と文法リファレンスにあります。

## 1. 3 つの形

YAML はほぼ次の 3 つでできています。

```bread
# ブレッドボードの実体配線図 (tommie-fence の bread フェンス)
title: LED と抵抗
board: half
parts:
  R1: resistor a5 a10 330
  D1: led b12(A) b13(K) red
wires:
  - +t5 -- a5 red
  - a10 -- b12
```

| 形 | 書き方 | 上の例 |
| --- | --- | --- |
| キーと値 | `キー: 値` (コロンの後ろに空白) | `title: LED と抵抗` |
| 入れ子 | キーの次の行から、**空白で字下げ** | `parts:` の下の `R1: ...` |
| 並び | 行の頭に `-` と空白 | `wires:` の下の 2 本 |

そのほかに、`#` から行末まではコメントです (空白の後ろの `#` だけ)。
フェンスの 1 行目の `# ブレッドボードの実体配線図 (...)` もコメントで、図には出ません。

## 2. 字下げのきまり

- 字下げは**空白だけ**です。タブは使えません。
- 同じ階層は同じ数の空白に揃えます。2 つが慣例です。
- キーの値が並びのとき、行頭の `-` は親のキーと同じ字下げでも、1 段下げても読めます。

## 3. 1 行で書く形 (フロー形式)

入れ子と並びは、`{ }` と `[ ]` で 1 行にも書けます。次の 2 つは同じ意味です。

```yaml
parts:
  R1: resistor a5 a10 330
```

```yaml
parts: {R1: resistor a5 a10 330}
```

```yaml
wires:
  - a10 -- b12
  - c13 -- -t13
```

```yaml
wires: [a10 -- b12, c13 -- -t13]
```

短いものは 1 行、長いものは行を分ける、と使い分けるのが読みやすい書き方です。

## 4. つまずきやすい所

| 書いたもの | 何が起きるか | 直し方 |
| --- | --- | --- |
| `title: 5 V: 電源` | 値の中の `:` と空白がキーの区切りに読まれ、エラーになる | `title: "5 V: 電源"` と引用符で囲む |
| `title: R1 #1 を使う` | 空白の後ろの `#` から先がコメントになり、消える | 引用符で囲む。または `#` を避ける |
| `label: @in` `label: %x` | `@` `%` `*` `&` `!` `[` `{` で始まる値は特別な意味に読まれる | 引用符で囲む |
| 字下げにタブ | 読めない | 空白に直す |
| `a5` `10k` `1.5,2.1` | 字として読まれる (番地・値・座標はそのままで良い) | — |

引用符は `"..."` でも `'...'` でも構いません。迷ったら囲んでおけば、字として読まれます。

## 5. 読めない行があっても止まらない

フェンスの中に読めない行があっても、tommie-fence のエディターは**読めた分を描き続けます**。
読めなかった行はそのまま残り、行番号つきで図の下に出ます。まず出た行を直し、図が戻るか見てください。
(その行の書き方の誤りは、行番号・行の中身・綴りを指す印で図の代わりに出ます。)

## もっと詳しく

- YAML そのものの仕様: [YAML 1.2](https://yaml.org/spec/1.2.2/)。
  tommie-fence は 1.2 として読むので、`on` `no` `yes` は真偽値でなく字です。
- 触りながら: [触ってみる](try-me.ja.md) を開いて、フェンスを書き換えてみてください。
