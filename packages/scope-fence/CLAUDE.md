# プロジェクト指示 (scope-fence)

Markdown の ` ```scope ` フェンスをオシロスコープの画面として描くライブラリ + CLI。
横断の作法は[リポジトリ直下の CLAUDE.md](../../CLAUDE.md)、
**このパッケージについてはここが正**。起こした経緯と決めは
`~/52-tommie-fence/docs/81`・`85` にある (private)。

## この図の物理 (設計が板の 3 つと分かれる理由)

**図の中に部品も板も無い。** 描くのは時間の関数 (電圧) で、そこから次が全部出てくる。

- **ネットリストも ERC もマップ (エディタの殻) も無い** (vna と同じ)。拡張には
  `FenceEditor` を渡さず、Problems に出す口 (`problemsOf`) だけを渡す
- 値は**理想** (`ch1: square 100Hz 1V` のような波形発生器の波 + `| rc 1ms` のような
  通す操作。画面の幅を 8192 点で標本化して計算する) と **測った CSV** (`data:` —
  WaveForms の Export) の 2 通り。破線と実線
- **vna との違いは 1 つの格子に ch を重ねること** (vna は単位ごとに枠を分けた)。
  2 ch を同じ格子で見比べるのがオシロの読み方そのもの (位相差・入出力)
- 波と単位の読み (`parseWave` `parseVolts` …) は **fence-kit の `wave.ts` `units.ts`**。
  spectrum フェンスと同じ綴りで書く

## 約束

1. **core はファイルを開かない**。`data:` は宿主が `DataSource` で渡す (CLI は `.md`
   の隣、拡張は `env.currentDocument` の隣)。**名前は `DATA_NAME` 1 か所で絞る**
   (`/` も `..` も通さない)。宿主の読み口は fence-kit の `readNeighbor` (vna と共用。
   シンボリックリンクを辿らず、通常のファイルだけを、上限まで読む)
2. **エスケープが唯一の防御** (板のフェンスと同じ)。図と帯に載る字は `escapeMarkup`、
   入力の断片を報告に載せる入口は `safeToken` だけ。CSV の `#` の頭書きは描かない
3. **読めなかったところは図の外に出す**。**格子は必ず描く** (空でも。54)。
   `data:` が読めないのはお知らせ (理想だけで図は出る)
4. **SVG に `NaN` / `Infinity` を書かない**。描く値は格子の縁に寄せる
5. **上限を置く** (`limits.ts`)。ch・操作・カーソル・Measurements・点数・ファイルの大きさ
6. **単位の無い数は断る** (直下の CLAUDE.md の文法の方針 1)。`1V` `1kHz` `1ms` と書く。
   素の数を受けるのは `gain` の倍率だけ (単位が無い量)
7. **理想も実測も同じ算法で測る** (`model/measure.ts` は点の列から測る)。道を 1 つにする
8. **補った既定のうち図の中身を決める物は言う** (`time:` と `trigger:` を書かなかったとき、
   pulse の duty)。見た目の既定 (V/div の Auto、テーマ) は状態の行に出るので言わない
