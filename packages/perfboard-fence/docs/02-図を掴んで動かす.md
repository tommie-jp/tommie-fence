# 図を掴んで動かす

図を見ながら部品や穴を掴んで動かし、フェンスの番地を書き換える操作。
**位置を穴番地で書く**フェンスなので、「動かす」は行の中の綴りを
差し替えるだけで済む。

## 2 つの入口

| 開き方 | どうなるか |
| --- | --- |
| タブの頭の一覧から `perfboard Editor` | `.md` のタブそのものが図のエディタになる |
| `Perfboard Fence: 図を掴んで動かす (マップ)` | エディタの横にマップを開く |

一覧は `.md` を開いたタブの頭 (`Text Editor ▾`) にあり、`Markdown Preview` や
`Markdown Editor` と並ぶ。古い VS Code では `View: Reopen Editor With...` から。

**既定の開き方は変わらない。** `.md` は今までどおりテキストエディタで開く。
いつもマップで開きたければ、一覧の「Set Default for '*.md'」で選ぶ。

## 掴むのは図そのもの

マップは**別に描いた升目ではなく、図そのもの**。穴の上に透明な当たり判定が
重なっているだけなので、見えている絵と掴む場所が食い違わない。

**道具は 4 つ。** 頭の帯で切り替える (`V` / `W` / `N` と、パレットで選ぶと
「置く」になる)。

| 道具 | 何をするか |
| --- | --- |
| 選ぶ (`V`) | 部品と配線を掴む。ドラッグで動かし、`Delete` で消す |
| 配線 (`W`) | 穴から穴へドラッグして 1 本引く |
| 節点 (`N`) | 穴を掴む。その穴に来ているものが丸ごと動く |
| 置く | パレットで部品を選ぶと、`Esc` まで置き続けられる |

掴む物が違えば意味も違うので、**同じ操作に混ぜない** — 部品はその 1 つだけが
動いて接続が変わり、節点は来ているものが丸ごと動いて接続は保たれる。

**動かすのはドラッグだけ。** クリックは選ぶだけで動かない (選んだものは
エディタの書いてある場所が光る)。

## 置く・消す・つなぐ

- **置く**: パレット (頭の折り畳み) で部品を選ぶ。**種類名・略記・和名**の
  3 通りで探せる。2 本足は穴から穴へドラッグ、3 本足は置きたい穴を 1 回押す。
  名前は**接頭辞ごとに最小の未使用番号**が付く
  (`D1` が LED なら、次のダイオードは `D2`)
- **消す**: 選んで `Delete`。**その部品を指す注釈も一緒に消える** (残しても
  指し先が無いので何も描かれない)。配線は連れていかない — こちらの配線は
  穴を指すので、部品が消えても行はそのまま正しい (**繋ぎ忘れになるので、
  帯の ERC が「つながっていません」と教える**)
- **つなぐ**: 配線の道具で穴から穴へドラッグすると `wires:` に 1 行増える。
  色は書かない (**色は後から欄で変える**もの)
- **最後の 1 つを消したら鍵ごと消える** (空の `parts:` は読めない)

## 回す・反転する

`R` で時計回り、`Shift+R` で反時計回り、`M` で反転。**掴んだ物によって行の
直り方が変わる**が、押す側から見ればどちらも 1 つの操作。

**足を並べて書く部品 (2 本足・3 本足)** — 穴の番地が動く。

- **アンカー (先に書いた足) は動かない。** 動かすと「回す」が「移動」になる
- 反転は**足の並びの入れ替え**。書かれた綴りをそのまま入れ替えるので、
  手で整えた空白も残る。3 本足なら両端が入れ替わり、真ん中はその場に残る
- 板の外へ出る回転は、**どの穴が出るのかを名指して**断る

**アンカー 1 つで置く形 (DIP / SIP)** — 向きの語が直る →
[部品の向き](01-syntax.md#部品の向き-r90--r180--r270--mirror)

- 語は**穴のすぐ後ろ**に入る (`U1: dip8 c3 r90 NE555`)。値は最後のまま
- 一周して元の向きに戻ったら語は消える (**前の空白ごと**消えて、行末に余りが残らない)
- 回転と反転は別々なので、回してから裏返しても回転は残る
- **回した先が板の穴に落ちることを見る。** 落ちない図は描けないので、
  掴んで回した人に帯だけが残らないよう、ここで断る

## 名前・種類・値を直す

部品を選ぶと下に欄が出る。`Enter` か欄を離れたときに行へ当たる。

- **名前**を変えると、鍵と**その部品を指す注釈**が一緒に変わる
- **種類**は置く前に確かめる (知らない種類は断る)
- **値**は `#` や YAML の記号を通さない — 行の形が壊れて値が黙って消えるため。
  **ラベルの欄は無い** (この文法に `l=` にあたる綴りが無く、字を添えたいときは
  注釈で書く)
- **足の数が変わる種類には替えない。** 穴の数が合わなくなると図が消えるので、
  替える前に断る

## 部品を動かす

**最初の穴がアンカー**で、部品は形を保ったまま平行移動する。

```yaml
R1: resistor b2 b6 10k
```

`R1` を `c2` へ動かすと `resistor c2 c6 10k` になる。値も名前も触らない。

板の外へ出る移動は、**どの足が出るのかを名指して**断る。格子は一様なので
(溝も電源レールも無い)、動く量は行と列の差そのもの。

## 節点を動かす

その穴に来ているものを丸ごと運ぶので、**接続は保たれる**。

`points:` で名前が付いていれば、直すのは**普通はその行き先の 1 行だけ**。

```yaml
points:
  IN: a1
parts:
  R1: resistor IN b6 10k
wires:
  - IN -- a2
```

`IN` の節点を `a3` へ動かすと `IN: a3` の 1 行だけが変わり、`R1` も配線も
綴りを変えずに付いてくる。**これが `points:` の存在理由**そのもの。
同じ穴を生の綴りでも書いていたら、そこも一緒に運ぶ — 置いていくと接続が
切れて、「丸ごと運ぶ」の約束が破れる。

**縮退は断る。** 寄せた先に自分のもう一方の足がある部品は長さ 0 になり、
図から消えてしまう。その組み合わせは動かす前に名指して断る。

## 接続が変わったら教える

**動かす前に止めない。** 掴んで放すたびに確認が出ると、位置を試しながら
決めるという本来の使い方で邪魔になる。移動の前後でネットリストを比べ、
**離れた接続と、つながった接続を動かしたあとに**帯へ並べる。

**全穴が独立している**ので、寄せただけでつながることは無い。導通は配線でしか
生まれないから、接続が変わったときは必ず配線か足の話になる。

`points:` で名前を付けた穴も**接続の相手として数える**。部品が 1 つしか
来ていないネットでも、名前から離れたことは知らせる値打ちがあるため。

## エディタと突き合わせる

マップとエディタは**互いに指し合う**。

- マップで掴むと、その部品 / 節点を**書いている場所がエディタで光る**。
  フォーカスは動かさない — 掴んでいる最中にエディタが前へ出ると、
  マップが隠れて置けなくなる
- エディタのカーソルを動かすと、指しているものが**マップで光る**。
  穴の綴りの上なら節点、それ以外は行が持っているもの (部品か配線)。
  `points:` の行はどこにカーソルがあってもその穴を指す

図の下の帯には、読めなかった行と ERC のお知らせ (繋ぎ忘れ・ショート・
浮きネット) が出る。**行を押すとエディタのその行へ飛ぶ**。
**繋ぎ忘れは図の上で沈黙する**板なので、直す場所を編集する場所と同じ窓に
出すことがとくに効く。

## 戻す・やり直す

タブそのものがマップのときは、VS Code の `Ctrl+Z` がそのまま効く。
横に開いたパネルのときは、パネルにフォーカスがあると `Ctrl+Z` が
エディタに届かないので、**パネルが自分で覚えている** (頭のボタンか
`Ctrl+Z` / `Ctrl+Shift+Z`)。

移動したあとにフェンスを手で書き換えていると戻せない。丸ごと書き戻すので、
当てると手で書いた分まで消えるため、黙って当てずに断る。

## いまできないこと

**足に `points:` の名前は書けない。** 名前を書けるのは配線の端で、部品の穴は
番地で書く (breadboard とはここが違う)。

**フロー形式 (`parts: {R1: …}`) の行は消せない・足せない。** その書き方では
行が 1 つのものに対応しないので、行ごと消すと鍵まで消える。動かすほうは
今までどおり効く。

## 書き換え方

**YAML を組み直さない。** 行の中の穴の綴りだけを差し替えるので、
手書きのコメント・整形・並び順がそのまま残る。
