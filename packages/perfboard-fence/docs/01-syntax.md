# perf フェンスの書き方

Markdown の ` ```perf ` フェンスに YAML を書くと、Markdown プレビューで
ユニバーサル基板の実体配線図になる。ここは文法の全部。
長い綴り ` ```perfboard ` も別名として**今後も動く** (短い綴りを読むのは 0.11.0 から)。
報告の名札はどちらで書いても `perf:`。
回路 1 つずつの例は [examples/](../examples/README.md) にある。

**一通り書ける。** 2 ピン・3 ピン・DIP・SIP の部品、基板の外の機器 (`device`)、
注釈 (`notes:`)、テーマと幅 (`style:`) まで。

## 基板 (`board:`)

**要る。** 基板の大きさが決まらないと穴の数が決まらず、番地も配置も読めない。

書き方は 2 つ — **穴数**か、**基板の名前**。

### 穴数で書く

**列 × 行**で書く。基板が「72×47mm」と長辺 × 短辺で売られているのと同じ順。

```perf
board: 12x7
title: 図01 12 列 7 行の板
```

![図01 12 列 7 行の板](out/01-syntax-1.svg)

大文字の `X` と前後の空白も受ける (`28 X 18`)。上限は `120x120`。

### 名前で書く

穴数を数えてある基板は、名前でも書ける。

| 名前 | 短く | 実寸 | 穴数 |
| --- | --- | --- | --- |
| `akizuki-a` | `a` | 155×114mm | 55 列 40 行 |
| `akizuki-b` | `b` | 95×72mm | 36 列 27 行 |
| `akizuki-c` | `c` | 72×47mm | 25 列 15 行 |
| `akizuki-d` | `d` | 47×36mm | 17 列 14 行 |
| `5x7cm` | | 50×70mm | 18 列 24 行 |
| `7x9cm` | | 70×90mm | 26 列 31 行 |
| `9x15cm` | | 90×150mm | 33 列 54 行 |
| `10x15cm` | | 100×150mm | 36 列 55 行 |
| `12x18cm` | | 120×180mm | 44 列 60 行 (実物で 44〜46 列 60〜65 行) |

表の下 5 行は海外の汎用基板 (縁のパッドと四隅の取付穴があるスルーホールの両面板) で、
穴数は作者が数えた。**名前には `cm` が要る** — 単位の無い `5x7` は
5 列 × 7 行の穴数として読む。横に置いた綴り (`7x5cm` = 70×50mm) は同じ基板を寝かせた
向きで、列と行が入れ替わる (24 列 18 行)。秋月の基板は寝かせない。

```perf
board: akizuki-d
title: 図02 名前で書いた板 (秋月 D タイプ)
```

![図02 名前で書いた板 (秋月 D タイプ)](out/01-syntax-2.svg)

**実寸の綴りでも同じ基板が出る。** `72x47mm` も `7.2x4.7cm` も `akizuki-c` になる。

**ただし綴りが違えば別の基板のこともある。** 72×47.5mm も「C タイプ」だが、
外形図の格子は 27 × 17 で 72×47mm (25 × 15) と違う。だから実寸で引けるのは、
**その綴りで売られている基板を数えたとき**だけにしてある。

### 実寸から穴数は計算していない

縁の余白は基板ごとにも辺ごとにも違い、取付穴がそこに入る。だから
**ミリを 2.54 で割っても穴数は出ない** (A タイプは 155×114mm で 55×40。
割り算だと 61×44)。上の表にあるのはメーカーの外形図の丸を数えた値で
(A と C は図面自身が `2200-Ø1.00NT` / `375-1.0ø NT` と穴数を書いている)、
数えていない基板は名前で引けない。

そのときは近い基板を挙げて返す。たとえば `board: 71x49mm` は
「近いのは `akizuki-c`」と言う — **70×50mm (7x5cm) と 72×47mm (秋月 C タイプ) は
別の基板**なので、近いだけの寸法を勝手に当てはめない。

**インダクタにも 3 桁コードを刷る** (`100u` なら `101`。µH 基準)。
**値には接頭辞を付ける** (`100u` `10m`。コンデンサも `100n` `47p` `10u`) — 素の数
(`470`) は µH とも H とも読めるので断る。実物には色帯の
ものもあるが、**帯にすると抵抗と見分けが付かない** — 同じ形の胴なので、色だけの
違いでは読めない。

**傾けて置いた部品は、キャプションも同じだけ傾く** (縦なら時計回りに 90 度、
斜めならその角度)。横のままだと、細長い部品の脇に長い字が伸びて胴や隣の配線に
被る。**上下がひっくり返る向きへは回さない** — 実物の部品はどちら向きに挿しても
同じものなので、名前が逆さまに出る理由がない。

**ピンや配線が入った穴は半田で埋まる。** 図では銀の玉になり、何も入っていない穴は
黒く抜けたまま残る — **どこを半田付けするのかが図だけで分かる**ようにするため。

**単位が無ければ穴数として読む。** `board: 72x47` は 72 列 × 47 行 (3,384 穴)
になる。ミリのつもりで書いても図は出てしまうので、そこはお知らせで言う。
持っている基板と同じ寸法 (`72x47`) だけでなく、**近い基板がある寸法** (`70x50` —
7×5cm の汎用基板のつもり) でも言う。`70x50` なら「穴数として読みました。70×50mm の
基板のことなら board: 7x5cm」。

### 格子を替える (`grid:`)

標準基板は作者が数えた穴数だが、実物は売り手で揺れる (12x18cm は 44〜46 列 60〜65 行)。
自分の基板を数えたら `grid:` で替える。

```yaml
board:
  size: 12x18cm
  grid: 43x58
```

`grid:` は **`列x行` で、図と同じ向き** (`18x12cm` なら横長で 58x43)。標準基板の名前
(または実寸) の `size:` にだけ書ける — 秋月の基板と `25x15` のような穴数には書けず、
断られる。数えた範囲の外の格子は図を出したうえで「数えていません」と言う
(12x18cm は 44〜46 列 60〜65 行の内側なら黙って受ける)。上限は穴数で書くときと同じ。

### スロット用の銅箔 (`slots:`)

基板をマップで書くと、大きさのほかに**基板そのものの性質**を足せる。いまあるのは
`slots:` 1 つで、**短いほうの両端に並ぶ細長い銅箔**を描く。

```yaml
board:
  size: 20x14
  slots: on
```

| 項目 | 書くもの | 既定 |
| --- | --- | --- |
| `size` | 穴数・名前・実寸 (スカラーで書くときと同じ綴り) | 要る |
| `grid` | 名前の標準基板の穴数 `列x行` (図と同じ向き) | 基板の数えた穴数 |
| `color` | 基板 (レジスト) の色 | `green` |
| `land` | 穴の銅箔 (ランド) の色 | `silver` |
| `slots` | 短いほうの両端の銅箔。`on` / `off` か、その色 | `off` |
| `h` | 基材の厚さ (`mm` を付ける) | `1.6mm` |
| `material` | 基材 (`FR-4` `CEM-3` `CEM-1` `FR-1` `FR-2` `FR-3`) | `FR-4` |

```text
color  green  blue  red  black  white  yellow  purple  bare   (と #RRGGBB)
land   silver  gold  copper  tin                              (と #RRGGBB)
```

**基材の厚さ (`h:`) と種類 (`material:`) は断面を描くときの値。** 上から見た基板の図は
変わらない。綴りは copper フェンスの `h:` と同じで、**単位 `mm` が要る** (`h: 1.6` は
「`1.6mm` と書きます」と言って断る)。基材は売り場の表記のまま書く — ガラスエポキシは
`FR-4`、ガラスコンポジットは `CEM-3`、紙フェノールは `FR-1` か `FR-2`、紙エポキシは `FR-3`。
大小は問わないが、**ハイフンの無い `FR4` は受けない** (正の綴りを 1 つにする)。
既定の 1.6mm・FR-4 は、手に入りやすいアリエクスプレスの両面スルーホール基板に合わせてある。
**名前の基板は基材を決めない** — 秋月の 72×47mm (`akizuki-c`) はガラスコンポジット (`CEM-3`) で、
同じ「C タイプ」の FR-4 版は 72×47.5mm の別の基板。名前で書いた基板も、基材は `material:` に書く。

```yaml
board:
  size: akizuki-c
  h: 1.6mm
  material: CEM-3
```

**基板の色とランドの色は表を分けてある。** 混ぜると基板に `gold`、ランドに `green` と
書けてしまい、綴りは通るのに実物にない基板が出る。

**銅箔には配線を半田付けできる。** `a0` (左端の外) や `a13` (12 列の基板の右端の外)
のように、**穴の並びのすぐ外の番地**を配線の端に書ける。マップからも押して引ける。
**部品は挿さらない** — 銅箔には穴が無いので、ピンの行き先にはならない。

**銅箔にも番号が出る。** `slots:` を書いた基板は、番号が `0` から `列数 + 1` まで
伸びる (縦長の基板なら行のほうが伸びる)。番号が出ていないと配線の端をどう書けばよいか
図から読めないため。

**`slots:` は色でも書ける** (`slots: gold`)。銅箔を出すかどうかと、その色は
1 つの指定で足りる。`land:` だけ書いたときはスロットもそのめっきになる
(実物も同じ工程で仕上がる)。

**色はテーマではなく基板に書く。** 図の配色 (`style: theme:`) を変えても
基板の色は動かないし、基板の色を変えても題や書き出しの字の色は動かない。
**基板に載る字の色は基板の明るさから決める** — 白い基板には黒い字、緑の基板には白い字。

- **穴ではないので挿せない。** 番地を持たず、ネットにもネットリストにも出ない
- 出るのは**短いほうの辺**。列が多い基板では左右、行が多い基板では上下
- 穴からは**穴 1 つぶん (2.54mm) 離す**。詰めると穴の列の続きに見えて、そこにも
  挿せると読める。銅箔を出した辺は、そのぶん基板の縁の余白が広がる
- **銅箔には番地がある** — 穴の格子のちょうど 1 つ外なので、`c0` や `c26`
  (25 列の基板) がその銅箔になる。配線を引けばネットに出る ([番地](#番地))
- **既定は描かない** — 銅箔の無い基板のほうが多く、無い基板に描くと
  「そこに何か付けられる」と読めてしまう
- `size:` を書かないとエラー。**大きさを当てて描くと、書いていない基板の図が黙って出る**

## 番地

**英字 + 数字**で `b3`。**どちらが行でどちらが列か、どちらから数えるかは基板のシルクで決まる**
([下](#英字と数字の振り方-silk))。穴数で書いた基板 (`board: 25x15`) は、英字が行 (上から)・
数字が列 (左から) で、`a` と `1` から数える。大文字でも受けて小文字に正規化する
(基板の印字が大文字のことがある)。

**図の端に出る名前は番地の綴りと同じ。** 図の端に `C` と `5` と出ている穴は、
フェンスにも `c5` と書く。基板を見て綴りを書き、図を見て半田付けするので、
基板・図・綴りの 3 つが同じ名前でないと取り違える。

行の名前は**表計算と同じ数え方**で伸びる。`z` の次は `aa`、その次が `ab`。
ユニバーサル基板は基板ごとに行数が違い、大きい基板は 26 行を超えるため。

```perf
board: 4x30
title: 図03 26 行を超える板
```

![図03 26 行を超える板](out/01-syntax-3.svg)

### 英字と数字の振り方 (`silk:`)

基板に刷ってある英字と数字は、基板によって逆になる。`board:` の `silk:` で選ぶ。

| `silk:` | 英字 | 数字 | 使う基板 |
| --- | --- | --- | --- |
| `board` (既定) | 名前の基板はその基板の刷りどおり。穴数で書いた基板は `fence` | 同左 | 手元の基板と見比べて組む |
| `fence` | 行、上から | 列、左から | breadboard フェンスと並べて読む図 |
| `alpha-rows` | 行、**下から** | 列、左から | 秋月の基板 |
| `alpha-cols` | **列**、左から | **行、下から** | 横に置いた汎用 5x7cm (アリエクスプレスなど) |

名前の基板の `board` は次のとおり。

| 基板 | 振り方 |
| --- | --- |
| `akizuki-a`〜`akizuki-d` | `alpha-rows` (短辺が英字、A が一番下の行) |
| `5x7cm` など (縦置き) | `fence` (長辺が英字で上から) |
| `7x5cm` など (横置き) | `alpha-cols` (長辺が英字、数字は下から) |

```yaml
board:
  size: 7x5cm
  silk: alpha-rows   # 書かなければ board (この基板なら alpha-cols)
```

**番地の綴りの形は変わらない** (どれも英字 + 数字)。変わるのは、英字がどちらの軸を
指すか、どちらから数えるかだけ。基板の外 (`0` と負) も同じ軸・同じ向きで続く。
下から数える振り方では、基板の外の「上」は `0` ではなく**最後の行より大きい**番号になる。

**`board:` を 0.31 までの綴りのまま読みたいときは `silk: fence`** と書く
(名前の基板の既定が変わったため。図が同じになるよう綴りを書き換える移行は
`node scripts/migrate-silk.mjs` が行う)。

### 基板の外を指す

**番地は基板の外へも出せる。** 列は `0` とマイナス (`a0` `a-1` `a-2`…)、
行は `0` とマイナスの英字 (`01` `-a1` `-b1`…)。0 を挟んで
**…-B -A 0 A B…** と間を空けずに並ぶので、基板の中と外で数え方が変わらない
(`a1` の左隣が `a0`、その左が `a-1`)。

| 綴り | どこ |
| --- | --- |
| `a-1` | a 行の、1 列目から 2 つ左 |
| `00` | 0 行 0 列 (基板の左上の外側の角) |
| `0-3` | 0 行の、3 つ左 |
| `-a1` | a 行の 1 つ上、1 列目 |
| `-b-2` | b 行の 2 つ上、2 つ左 |

基板の外を指せないと、**縁の銅箔 (スロット) や、基板から張り出す部品の行き先**を
書けない。スロットの銅箔は穴の格子のちょうど 1 つ外に並ぶので、
**`0` 列と `列数+1` 列がそのままその銅箔**になる (25 列の基板なら `c0` と `c26`)。
そこへ配線を引けば**銅箔に半田付けした**ことになり、ネットにも出る。

**離れすぎは断る。** 基板の外へ出られるのは 4 つ先まで。無制限にすると、
番地 1 つで画布をいくらでも伸ばせる (穴数に上限を置いたのと同じ理由)。

**基板の外に穴は無い。** 図に穴は描かれず、そこに挿せるわけでもない —
指せるのは位置であって、載っているのは銅箔か、基板から張り出した部品の脚。

### 交点の間 (注釈だけ)

**注釈だけは交点の間に置ける。** 番地のうしろに**組**を書くと、そこから
1/10 升ずつずれた場所になる (`d3c3` = `d3` から 0.2 行下・0.3 列右。
組の英字は `a` = 0、数は 0〜9)。

升目 (Fence Editor) は**既定で 1/10 升**を送るので、字を穴の並びの隙間や
基板の外へ寄せられる。`Shift` を押している間だけ升ちょうどに吸い付く。

**ピンは穴に挿す**ので、部品・配線・節点にこの綴りは書けない
(書くと「穴の間には置けません」と返る)。breadboard も同じ綴り。

## 題 (`title:`)

図の上に出る題。文章から「図03 を直して」と指せるようにするためのもの。

```yaml
title: 図01 RC ローパス
```

## 部品 (`parts:`)

`名前: 種類 穴 穴 値` を 1 行ずつ。部品は**2 つの穴を結ぶ線の上に寝る**。

```perf
board: 12x6
title: 図04 部品の置き方
points:
  IN: a1
  OUT: a12
parts:
  R1: resistor b2 b6 10k
  D1: led b8 b10 green
wires:
  - IN -- b2
  - b6 -- b8
  - b10 -- OUT
```

![図04 部品の置き方](out/01-syntax-4.svg)

**名前**は英数字と `_` `-` で 32 字まで。配線から指せる形にする。
**同じ名前は 1 つだけ** — 2 つあると、配線がどちらを指すのか決まらない。

**種類**は 2 ピンが 29、3 ピンが 7、それに USB コネクタ、`dipN` / `sipN` とマイコンボード。

```text
2 ピン  resistor  capacitor  led  diode  inductor  crystal  buzzer
        photoresistor  thermistor  thermistor-ntc  thermistor-ptc  varistor
        zener  schottky  photodiode  phototransistor  varicap  diac  reed  fuse  lamp  ferrite-bead  sma
        speaker  mic  battery  solar  switch (a 接点)  switch-nc (b 接点)
3 ピン  transistor  potentiometer  thyristor  triac  slide-switch  regulator  ic3 (3 ピンの IC)
4 ピン  transformer
USB     usb-a (穴は VBUS GND D+ D- の順に 2 つから)  usb-c (穴は GND D+ D- VBUS の順に 4 つ)
パッケージ  button (a 接点)  button-nc (b 接点)  dip4〜dip40 (偶数)  sip2〜sip40
ボード      pico  pico-w  pico2  pico2-w  tang-nano-9k
```

`ferrite-bead` はリード付きのフェライトビーズ。帯の無い濃い灰色の円筒で描く。
値は型番やインピーダンスをそのまま書く (`FB1: ferrite-bead i6 i11 600R@100M`)。
抵抗と同じ軸物なので、隣の穴には挿せない (番地の差 3 = 4 穴分が目安)。

マイコンボードは **breadboard と同じ綴り・同じピン名**で書ける (`U1.GP0`)。
表を 2 つのフェンスで共有しているので、同じ回路をどちらでも書ける。

**書く穴の数は形が決まる。**

| 形 | 書く穴 | ピンの位置 |
| --- | --- | --- |
| 2 ピン | 2 つ | 書かれたとおり |
| 3 ピン | 3 つ | 書かれたとおり (ピンは曲げられる) |
| 4 ピン | 4 つ | 書かれたとおり (巻線の端の並びは品ごとに違う) |
| USB (`usb-a` / `usb-c`) | Type-A は 2 つから 4 つまで、Type-C は 4 つ | 書かれたとおり。ピンの名前は書いた順に、Type-A は `VBUS GND D+ D-`、Type-C は `GND D+ D- VBUS` |
| `button` | 1 つ (左上のピン) | パッケージが決める。4 本が 2 穴角の四角に並ぶ |
| `dipN` | 1 つ (胴の左上) | パッケージが決める。2 列の間隔は 300 mil = 3 穴 |
| `sipN` | 1 つ (1 番ピン) | パッケージが決める。1 列に並ぶ |
| ボード | 1 つ (胴の左上) | パッケージが決める。2 列の間隔は 0.7 インチ = 7 穴 |

DIP の番号は**実物を上から見た付き方** — 切り欠きを左にすると 1 番は**左下**
(アンカーの 3 行下)。下の列を右へ数えて、折り返して上の列を左へ戻る (反時計回り)。
アンカーは胴の左上の穴で、8 ピンなら 8 番がそこに挿さる。図には 1 番ピン側の
切り欠きを描く (**無いと 180 度回して挿せてしまう**)。
0.10.0 までは 1 番を左上に置いていて、実物を裏から見た並び (鏡像) だった。

略記も書ける (`r` `c` `l` `d` `q` `tr` `pot` `scr` `reg` `ec` `ecap` `ldr`
`ntc` `ptc` `xtal`)。
**畳んだ先の正式名しか出口には出ない** — 図・エラー・ネットリストは正式名で揃う。

**姿**は種類のあとに `/` で書く (`capacitor/ceramic`)。
書ける姿は `capacitor` が `ceramic` `film` `electrolytic` `tantalum`、
`led` と `phototransistor` が `3mm` `5mm`、3 ピンの 5 種 (`ic3` を含む) が `to92` `to220`、
`crystal` が `hc49` `cylinder`、`sma` が `male` `female` `male-edge` `female-edge`、
`usb-a` と `usb-c` が `male` `female` (差し込み・受け口。書かなければ受け口)、
`resistor` が `quarter` `half` (1/4W・1/2W)、
ダイオードの仲間が `do35` `do41` (ガラス管・黒いプラスチック)、
`inductor` が `axial` `radial` (軸物・立てた缶)、
`potentiometer` が `trimmer` `knob` (半固定・ボリューム)。
面実装の姿 (`transistor/sot346-dip` `transistor/sot346` `resistor/2012` `dip8/sop` など) は
[面実装](#面実装-sot346-dip--sot346--2012) の節にまとめた。
**書ける姿はすべて図の形が変わる** — 描き分けない姿は受け取らない。

**3 ピンの `to220` は実物の写真と同じ向き — ピンが下、放熱タブが上。** ピンの穴の行から上へ、
取り付けねじの穴のあるタブと黒い樹脂の胴が伸びる (穴の位置は変わらない。胴を回す
(`R`) と、タブも一緒に回る)。**`regulator` と `ic3` は、部品の値 (`7805` `LM317` など) を
胴に白い小さな字で刻む** — TO-220 は樹脂の面の真ん中、TO-92 は丸い側に、胴に収まる大きさで刻み、
長い型番は字を縮める。値を書かなければ何も刻まない。`transistor` などほかの 3 ピン部品と、
変換基板の姿 (`sot23-dip` など) は今までどおり。

### 同軸コネクタ (`sma`)

縦置きのピンは**中心導体と GND の 2 本**。実物の GND は 4 本だが、図とネットリストで
意味を持つのは「どこが中心でどこが GND か」の 2 つ。**横置き (端面実装) は 3 本** —
中心導体と、凹の両端の先端。

| 姿 | 置き方 | 図 |
| --- | --- | --- |
| `male` / `female` | 基板の上に立てる (縦置き) | 上から見た丸。オスは中心にピン、メスは穴 |
| `male-edge` / `female-edge` | 基板の縁に載せる (横置き・端面実装) | ねじ部・ねじなし・台座 (1mm) の 3 段。台座の右端が基板の縁に来て、そこから先は**凹の形** (上下にアース、中心導体が凸)。**ピンは 3 本** — 中心導体と、凹の両端の先端 |

**横置きは 3 ピン。** `J1: sma/female-edge c1 b0 d0` — **中心導体を先に、
凹の両端の先端をあとに**。実物の凹は基板の縁を上下から挟んでいて、半田付けするのは
腕の先端の 2 点、つまり**中心線の上下の行の縁の銅箔**に来る (上の例なら `c` 行の
中心導体に対して `b` 行と `d` 行)。**先端は片方だけ書けばよい** —
`J1: sma/female-edge c1 d0` と書けば、もう片方 (`b0`) は中心線を挟んで反対側に
決まる。凹は 1 つの金物なので、**2 本の先端は配線を引かなくても同じネット**に
乗る — ジャンパはどちらか片方へ付ければよい。先端を中心導体と同じ行に書くと断る
(実物の腕は中心線には来ない)。載せる辺は中心導体から一番近い縁で決まる。
胴は基板の外へ出るぶん**画布が広がる** (切って描くと、図を見た人は切れたことに
気づけない)。

**値**は残り全部。空白を含んでよい (`100n 50V`)。
抵抗の値はカラーコードを塗る (`10k` `4k7` `2.2M`、素の数 `220` は Ω)。`0` (0Ω の
ジャンパ) は黒の帯 1 本。**抵抗として読めない値は断る** (`whatever`、許容差が 2 つの
`10k 1% 2%`) — 既定の帯で描くと、図を信じた人が違う抵抗を挿す。
**コンデンサとインダクタの値には接頭辞を付ける** (`100n` `47p` `10u`)。素の数 (`47`) は
pF とも F とも読めるので断る。頭が数でない語 (`電解`) はラベルとしてそのまま出す。
**帯の本数は値の桁数で決まる** — 2 桁で書ける値は 4 帯 (数字 2 + 乗数 + 許容差)、
3 桁要る値は 5 帯。実物も E24 が 4 帯、E96 が 5 帯なので、書いた値がそのまま帯になる。

許容差は値のうしろに書ける (`10k 5%`)。**書かなければ ±1%** — 金属皮膜 (金皮) の
標準で、いま手に入る抵抗のほとんどがこれ。温度係数を足すと 6 帯になる
(`10k 1% 50ppm`)。**色を持っていない許容差・温度係数 (`10k 3%`) は断る** —
近い値へ丸めると、実物と違う帯が出て図を信じた人を間違えさせる。
LED は値を色として読む (`red` `green` `blue` `yellow` `white` `orange`)。

**書く穴の数を超えた番地は、黙って値にせずエラーにする。** ピンを 1 本多く書いた
つもりの人が、「値 b9」と書かれた図を見て気づけないまま終わるため。

ただし**この基板に載らない番地は書き間違いではない**。型番や値は番地とそっくりの
綴りをしていて (`NE555` は ne 行 555 列、`C1815` は c 行 1815 列、容量のコード
`C102` は c 行 102 列)、番地として弾くと正しい図が毎回叱られる。**書いた基板の
大きさ** (と基板の外に指せる 4 つ先) を超える綴りは型番や値のほう。`board:` を
`parts:` より後に書いても同じに読む。

### USB コネクタ (`usb-a` / `usb-c`)

USB の受け口・差し込みを**変換基板ごと**描く。Type-C の受け口は面実装で穴に
挿せないので、実物も変換基板に載せてから挿す。図は
[examples/09-usb.md](../examples/09-usb.md)。

**穴はピンの名前の順に書く** — Type-A は `VBUS GND D+ D-`、Type-C の変換基板は `GND D+ D- VBUS`。
Type-A は**書いた数だけピンがある**ので、電源だけの変換基板は 2 つ、USB 2.0 は 4 つ。
Type-C の変換基板は 4 本のピンヘッダなので、**4 本とも書く** (`J1: usb-c/female a8 a9 a10 a11`)。
**書いた穴は、基板の後ろの縁に並ぶ四角いパッド**で、基板はそこから差し込み口の側へ 4.5 穴ほど伸びる。
ピンの並びは製品ごとに違うので決め打たず、**書いた穴がそのままピン**になる
(表の順に並べ替えて書く。`J1: usb-a c3 c6 c5 c4` なら c3 が VBUS、c6 が GND)。

- **ピンの名前はネットリストと ERC に出る** (`J1.VBUS`)。配線はピンの穴へ引く
  (部品のピンを名前で指せるのは基板の外の機器だけ — ほかの部品と同じ)。
- 書かなかったピンは無いものとして扱う。**書いたピンがどこにもつながっていなければ
  ERC が言う** (`J1.D+`)。使わないなら書かない。Type-C の変換基板は 4 本とも書く (パッドの数が実物と合う)
  ので、**挿したまま使わないピンは [`unused:`](#使わないピン-unused) に並べる** (`unused: [J1.D+, J1.D-]`)。
- **差し込み口は基板の中心から遠い側**を向く — 縁の近くに置けば、そのまま縁を向く。
  基板からはみ出すぶんは、題と基板の間 (下なら基板の下) を空けて描く
  (切って描くと、図を見た人は切れたことに気づけない)。
- 姿は `male` (差し込み。金物が変換基板の縁から出る) と `female` (受け口、既定)。
  ピンの名前は変換基板に刷る。
- **Type-C の受け口の金物には `USB-C` と刻む** (口の縁のすぐ内側、天板の窓と口の暗がりの間)。
  同じ形の変換基板が並んでも種類が図で読める。差し込み (`male`) と Type-A には刻まない。
- breadboard・circuit とも**同じ種類名・同じピンの名前**で書ける。

### 面実装 (`sot346-dip` / `sot346` / `2012`)

面実装の部品は**変換基板に載せた姿**と、**この基板に直付けした姿**の 2 通りで書ける。
図は [examples/10-smd.md](../examples/10-smd.md)。

| 書き方 | 意味 | 受け取る基板 |
| --- | --- | --- |
| `transistor/sot346-dip` | 変換基板 (秋月の「DIP 化基板」など) に載せたまま挿す。ピンはピンヘッダ | breadboard と perfboard |
| `dip8/sop` | SOP の IC を DIP 化した変換基板。書くのは DIP と同じくアンカー 1 つ | breadboard と perfboard |
| `transistor/sot346` `resistor/2012` | この基板に直付けする | perfboard だけ |

書ける姿:

| 種類 | 変換基板 | 直付け |
| --- | --- | --- |
| `transistor` | `sot23-dip` `sot346-dip` `sot89-dip` | `sot23` `sot346` |
| `regulator` | `sot23-dip` `sot89-dip` | `sot23` |
| `resistor` `capacitor` | — | `1608` `2012` `3216` |
| `led` | — | `1608` `2012` |
| `diode` `zener` `schottky` | — | `sod123` `sod323` `do214ac` |
| `dipN` | `sop` `tssop` | — |

- **S-Mini (東芝) は `sot346`** と書く。SC-59・SOT-346 と同じ物で、SOT-23 (`sot23`) と
  同じ 0.95mm のピンで胴が 0.3mm 広い。図も実寸で描き分ける。
- **別名は綴りとしては受け取らない** (`s-mini` `sc59` `0805` `sma`)。書くと
  「`s-mini` は `sot346` と書きます」と言って断る — 同じ物が部品表に 2 つの名前で
  並ばないように。チップの大きさは JIS の mm の呼び名 (`2012` = インチの 0805)。
- **直付けの置き方は姿が決める。** チップと SOD は隣の穴 (上下か左右) に跨ぎ、
  `do214ac` は 2 穴離し、SOT は**三角** — 1 番と 2 番のピンを隣の穴に、3 番を次の行の
  1 番か 2 番の隣に (`Q1: transistor/sot346 d5 d6 c6`)。SOT の 1 番と 2 番のピンの間は
  1.9mm で、隣の穴 (2.54mm) のランドに載る。**違う置き方はお知らせで言う**
  (図はそのまま描き、ピン先から穴への線に届かない分が出る)。軸物の
  「ピンの間隔が狭すぎます」は直付けには言わない。
- 胴は**実寸で描き、ピンの間隔では伸びない**。当たり判定も同じ形。直付けの SOT の胴は
  1 番・2 番の行と 3 番の行の間に載るので、そこに別の部品の胴を置くと重なりを言う。
- **ピンの並びは品種ごとに違う** (2SC2712 は 1 = B、2 = E、3 = C)。SOT は穴をピンの
  番号の順に書く。図はどのピンが何かを主張しない。
- `dipN/sop` のピンの番号は DIP と同じ。図には番号を刷らず、1 番側の端の白い点と
  IC の 1 番の窪みで向きを示す。**SSOP は無い** — 変換基板の列の間隔が 600mil (7 穴) で、
  `dipN` の 300mil に載らない。
- チップの印字 (`103` など) は描かない。図の大きさでは字が読めない。
- パレットから 1 穴で置くと、直付けの姿は置き方どおりに穴を並べる
  (`resistor/2012` は隣の穴、`transistor/sot346` は三角)。

### DIP のピンの名前

**`dipN` の型番が下の表にあれば、胴に番号と名前の両方が出る** (`U1: dip8 e6 NE555`)。
番号は胴の縁 (ピンのすぐ内側)、名前は**胴の中、番号のすぐ内側**。この基板の線はピンの穴から出るので、
胴の外に書くとピンから出る線が名前を横切る (ブレッドボードは胴の外)。立てた胴 (`r90` / `r270`) は
両側の名前で胴の幅が埋まるので、型番などのキャプションを胴の下に出す。
名前の字の大きさは胴の片側ごとに 1 つ。長い名前は短い隣の名前の空いた所へはみ出してよく、
それでも縮むときは `GROUND` を `GND` と刷り、下限 (4.5) でも入らない `/` で 2 つの働きを並べた

### ピンに名前のある DIP 型 (`relay` / `photocoupler` / `seg7` / `dip-switch4` / `dip-switch8`)

リレー・フォトカプラ・7 セグは、**DIP のピンの位置のうち、ピンのある所に名前が付いた物**
として置く。書き方は DIP と同じ (胴の左上の穴 1 つ、`@` は付けない) で、ネットリストに
ピンの名前で出る (`K1.COM1`)。表は breadboard・circuit と同じ (fence-kit)。リレーとフォトカプラの
胴には DIP と同じく**番号と名前の両方**が出る (7 セグは面を描くので名前だけ)。

```yaml
parts:
  K1: relay c3                 # G5V-2 (姿を書かなければ表の最初)
  U1: photocoupler/pc817 c14
  DS1: seg7 g14
  SW1: dip-switch4 c24
```

| 種類 | 姿 (品名) | 列の間 | ピン (DIP の位置) |
| --- | --- | --- | --- |
| `relay` | `g5v-2` (Omron G5V-2、2 回路) | 3 穴 | `A1` (1) `COM1` (4) `NC1` (6) `NO1` (8) `NO2` (9) `NC2` (11) `COM2` (13) `A2` (16)。1 と 16 がコイル |
| `photocoupler` | `pc817` (シャープ PC817) | 3 穴 | `A` (1) `K` (2) `E` (3) `C` (4) |
| `seg7` | `5161as` (0.56 インチ 1 桁、カソード共通) | 6 穴 | `e` (1) `d` (2) `COM1` (3) `c` (4) `dp` (5) `b` (6) `a` (7) `COM2` (8) `f` (9) `g` (10) |
| `dip-switch4` / `dip-switch8` | `slide` (スライド型、4 連・8 連) | 3 穴 | `A1`〜`A4` (1〜4) `B4`〜`B1` (5〜8)。8 連は `A1`〜`A8` (1〜8) `B8`〜`B1` (9〜16)。**k 番のスイッチは `Ak` と `Bk` の間の接点** |

- **ピンの無い位置には何も挿さない** — G5V-2 は DIP16 の 16 か所のうち 8 か所だけにピンがある
- 列の間は種類で決まる (7 セグは 6 穴。1 番ピンの列はアンカーの 6 行下)
- 何も書かなければ図と部品リストに品名 (`G5V-2`) が出る。7 セグは面 (8 の字) を描く
- **DIP スイッチはピンどうしをつながない** (開いた接点)。ネットリストには連の数ぶんの別々のピンで出る。胴には品名の代わりにつまみの溝を連の数だけ描く (ON の向きは品ごとに違うので字では刷らない)
- ID の接頭辞は `K` (リレー)・`U` (フォトカプラ)・`DS` (7 セグ)・`SW` (DIP スイッチ)
- 図は [例 11](../examples/11-named-chips.md)

### 部品の向き (`r90` / `r180` / `r270` / `mirror`)

**アンカー 1 つで置く形 (`dipN` / `sipN` / 名前付き DIP) だけ**が向きの語を持つ。穴のすぐ後ろに
書く。ピンを並べて書く部品 (2 ピン・3 ピン) の向きは**穴の順そのもの**なので、
語を書くと断る — 同じことを 2 通りで書けるようにすると、食い違ったときに
どちらが本当か決められなくなる。

| 語 | 意味 |
| --- | --- |
| `r90` / `r180` / `r270` | **時計回り**にその角度 |
| `mirror` | 左右を反転。**1 列の形 (`sipN`) だけ** — DIP や名前付き DIP は実物を裏返して挿せないので断る |

**両方書くときは反転してから回す** (`J1: sip4 c3 r90 mirror`)。順は問わない。
同じ種類を 2 回書いたら断る。**語彙と意味は circuit フェンス・breadboard
フェンスと同じ**なので、同じノートで書くときに覚え直さなくてよい。

```perf
title: 図05 向きを書いた DIP
board: 16x16
style:
  check: off
parts:
  U1: dip8 c3 NE555
  U2: dip8 c12 r90 NE555
  U3: dip8 k6 r180 NE555
```

![図05 向きを書いた DIP](out/01-syntax-5.svg)

**アンカーの穴は動かない。** 回るのは残りのピンだけなので、書いた番地に挿さるピンは
変わらない (DIP なら最後の番号のピン)。切り欠きは**パッケージの端**、1 番ピンの側に出る。

**回した先が基板の穴に落ちることを見る。** 基板の外の番地は穴ではない (縁の銅箔や、
基板から張り出す先) ので、そこへピンが来る図は実物では組めない。**回すと縁を
踏みやすい**ので、はみ出したピンを名指して断る。

```text
perf: 4 行目: U1 のピン f0 が基板の穴ではありません (回した先が基板から出ています)
```

## 配線 (`wires:`)

`- 穴 -- 穴` を 1 行ずつ。**2 つの穴をまっすぐ結ぶ。**
経路探索は無い — 溝もレールも無く、どの穴も同じ格子の上にあり、実物のジャンパも
2 点を最短で結ぶ。**書かれたとおりに描く**ので、はんだ付けの手順書になる。

色は後ろに書ける。名前か、`#RRGGBB` の綴り。

**書かなければ基板の色に合わせて選ぶ。** 緑や黒の基板には明るい線、白い基板には
暗い線が出る。既定を 1 つの灰色に固定すると、**同じ濃さの基板で線が沈む**ため。
基板の色 (`board: color:`) を変えれば線の色も一緒に動く。
**書いた色は動かさない** — あちらは実物の被覆の色なので、読みにくくても
書いたとおりに描く (図と手元の線を見比べるためのもの)。

```text
red  black  white  gray  grey  orange  yellow  green  blue  purple  brown  pink
#ff0000  #f00  (大小は問わない)
```

**名前のほうが読んで分かる**ので、実物の被覆の色に当たるものは名前で書く。
`#RRGGBB` は手元の線の色に寄せたいときのためのもの。

**そのどちらでもない綴りは書式エラー。** 色は SVG の属性へそのまま流れるので、
`red" onload="…` のような綴りが属性を割って出ないように、
**持っている名前か、字面が厳密に色である綴り**の 2 通りだけを通す。
注釈 (`notes:`) の色も同じ語彙。

**途中で交差する線は跨いで引く。** この基板は穴どうしが何もつながっていないので、
導通が生まれるのは配線の**両端の穴だけ**。線の途中で別の線と重なっても、そこは
ただの交差で何も起きない。ところが図の上では 2 本の線が同じ点で出会うので、
**半田付けした接点に見える**。あとに書いたほうを半円で跨がせて、渡っているだけだと
形で言う (実物でもジャンパは相手をまたいで渡るので、見たままでもある)。
**穴の真上で渡るときは半円を大きくして**、ランドと半田の玉に重ならないようにする。
膨らむ向きは、横寄りの線は上、縦寄りの線は右にそろえる。

**端が別の線の途中に乗っているものは跨がない。** そこは交差ではなく書き方の
問題で、跨いでも読めるようにはならない — 穴を通る 2 本に分けて書く。

## 穴の名前 (`points:`)

`名前: 番地` を 1 行ずつ。配線の端にその名前を書けるようになり、
**ネットの名前にもなる**。

```perf
board: 12x6
title: 図06 points で名前を付ける
points:
  VCC: a1
  GND: f1
parts:
  R1: resistor b3 b7 4k7
wires:
  - VCC -- b3 red
  - b7 -- GND black
```

![図06 points で名前を付ける](out/01-syntax-6.svg)

**番地と同じ綴りは名前にできない。** `b3: c5` と書けてしまうと、`b3` がどちらを
指すのか読む人にも処理にも決まらなくなる。

名前を付けた穴は**「基板の外へ出る」意思表示**として扱う。電源や信号の出入口が
「つなぎ忘れ」と言われないようにするため。**使わないピンを黙らせる目的には使わない**
(`unused:` を使う)。名前の意味が違い、読む人が「ここから何かが出入りする」と取り違える。

## 使わないピン (`unused:`)

**意図して使わないピン**を `部品の名前.ピンの名前` で並べる。ERC の「どこにもつながっていないピン」から
外すだけで、図には何も描かない。電源だけを取り出す USB-C 基板の `D+` `D-` のように、
**挿したまま使わないピン**に使う。

```yaml
unused: [J1.D+, J1.D-, J2.D+, J2.D-]
```

- 書けるのは**部品か基板の外の機器のピン**の名前 (`J1.D+`・`AD.1-`)。穴の番地では書かない
  (基板を替えたり番地のシルクを替えたりしても書き直しが要らない)
- **ほかの ERC は変わらない** (短絡・胴の重なり・空中配線は今までどおり)
- **部品に無いピンは断る** (`unused: に書いたピンがありません`)。綴りの誤りを黙って通さない
- **書いたピンが実際は配線されていたらお知らせを出す** (`unused: に書いたピンがつながっています`)。
  後から配線を足したとき、古い印が嘘にならない
- 書き方は `[J1.D+, J1.D-]` でも、1 行ずつの `- J1.D+` でもよい。2 つ書くとエラー (1 つにまとめる)

## 意図して短絡した部品 (`shorted:`)

ピンが全部同じネットに来る部品は、ERC が「配線で短絡しています」と言う (抵抗を入れたつもりが線で跨いでいた、という
取り違えを拾うため)。**中心導体とシェルを線でつないだ SMA の Short** のように、**意図して短絡した部品**は、
最上位の `shorted:` に**部品の名前**を並べて、そのお知らせから外す。

```yaml
shorted: [J2]
```

- 書くのは**部品の名前** (`J2`)。ピンの名前 (`J2.1`) ではない
- **短絡のお知らせだけ**を外す。ほかの ERC (つながっていないピンなど) は変わらない
- **書いた部品が短絡していなければお知らせを出す** (`shorted: に書いた部品が短絡していません`)。線を外したあとに古い印が残って、図と食い違うのを防ぐ
- **部品に無い名前は断る** (`shorted: に書いた部品がありません`)。2 つ書くとエラー

## 基板の外の機器 (`device`)

電池・スピーカー・測定器のように**盤面に載らないもの**。`parts:` の中に
**入れ子で**書く — ピンの名前の並びを持つので 1 行に畳めない。

```perf
board: 12x8
title: 図07 板の外の機器
parts:
  R1: resistor c3 c7 470
  D1: led c9 c11 red
  BAT:
    type: device
    at: top
    label: 電池 3V
    pins: + -
wires:
  - BAT.+ -- c3
  - c7 -- c9
  - c11 -- BAT.-
```

![図07 板の外の機器](out/01-syntax-7.svg)

| 項目 | 書くもの | 既定 |
| --- | --- | --- |
| `type` | `device` (**必ず書く**) | — |
| `at` | `top` / `bottom` (帯に並べる) か**番地** (そこに置く) | `top` |
| `label` | 図の箱に出る言葉 | 名前そのまま |
| `pins` | ピンの名前。空白区切りか YAML の並び | — |

**`at:` に番地を書くと、その場所に置く。** 基板の外の番地なので `-c1` (基板の上) や
`n5` (基板の下) のように書く ([番地](#番地))。**箱の左上がその番地**に来て、ピンは箱から
基板の側へ出る。**ピンは穴の格子に載り**、1 本目が書いた番地の列、次が 1 穴どなり…と
並ぶ。こうすると**「そのピンのいちばん近い穴」が迷いなく決まる**ので、機器のピンから
まず真下 (真上) の穴へ落として、そこから基板の上を配線できる。

**基板の上に置くなら `-b` 行より上。** 箱は番地から下へ伸びるので、`-a` や `0` に置くと
基板の縁と列の名前に被る。被ったときは、避けられる番地をお知らせで言う
([言われること](#言われること))。

帯に並べると置きたかった場所と関係なく散るので、**並べ方を自分で決めたいときは
番地で書く**。基板の寸法には機器のはみ出すぶんも入るので、題や書き出しと重ならない。
**ピンの名前は箱の内側**に書く — 外に出すと基板の列番号や配線に重なる。
機器のピンと配線は基板の上の列の名前を必ず横切るので、**行と列の名前はそれより上に、
地の色で縁取って描く** (線の下に敷くと、配線の行く先の列の名前が隠れる)。

**ピンは `+ -` のように空白で区切って 1 行に書ける。** YAML の並び (`[+, -]`) に
書くと `-` に空白が続くと箱の始まりに読まれて `["+", "-"]` と括らされる。電池の端子を
書くたびに引っかかる罠なので、1 行の書き方を正にしている。

**入れ子なら機器、とは決めない。** `type: device` を書かない入れ子は断る —
部品を書き間違えて字下げした人が、基板の外に箱が出ているのを見て
気づけないまま終わるため。

配線からは `名前.足` で指す (`BAT.+`)。番地にも `points:` の名前にも `.` は
現れないので、綴りだけで機器のピンだと分かる。

**機器へつなぐ配線も基板の上まで線を引く。** 電池やスピーカーの線も、実物では基板の穴に
半田付けする。どの穴へ行くのかが図に出ないと、帯に浮いた箱と基板が結び付かず、
組む人が図から手を動かせない。色を書けばその色で引く。
**機器どうしを結んだ配線だけは基板に触れない**ので線が無く、色を書いたときは
その旨のお知らせが出る (黙って消すと、効かない指定を書き続けることになる)。

## 注釈 (`notes:`)

図に印を付けて、文章から指せるようにするためのもの。**回路の一員ではない**
(ネットにもネットリストにも出ない)。

```perf
board: 12x8
title: 図08 注釈
points:
  IN: a1
  GND: h1
parts:
  R1: resistor c3 c7 10k
wires:
  - IN -- c3
  - c7 -- GND
notes:
  - mark c3 red
  - box b2 d8 blue
  - arrow f4 c5
  - text f6: ここから電源
```

![図08 注釈](out/01-syntax-8.svg)

| 印 | 書き方 | 出るもの |
| --- | --- | --- |
| `mark` | `mark 番地 [色]` | 穴を囲む丸 |
| `box` | `box 番地 番地 [色]` | 2 つの番地を対角にした枠 |
| `arrow` | `arrow 番地 番地 [色]` | 1 つ目から 2 つ目への指し棒 |
| `text` | `text 番地 [語]: 字` | その穴のそばに出る字。語は色・向き・`large`・`bold` |
| `source` | `source [色]` | **そのフェンスの中身**を図の下に書き出す |
| `parts` | `parts [色]` | **部品表**を図の下に出す |

**`text` だけは字を `:` の後ろに書く。** 番地のうしろに引用で字を書く
(`- text c3 "R1: resistor …"`) と、YAML がコロンで切るので字の頭 (`"R1`) が語として
読まれ、「注釈の知らない語です」と言われる。**字の中にコロンと空白の並びが
あるときは、`:` の後ろの字を引用で囲む** (`- text c3: "R1: resistor a1"`)。囲まないと
YAML の構文エラーになる。**3 つのフェンスで同じ形**。

**番地のあとに書けるのは語だけ** (色と向き、`text` はさらに見た目。順不同)。字と語が `:` で分かれるので、
`text` にも色を書ける (`- text f6 blue: ここから電源`)。**色の名前で始まる字は色に
ならない** — `- text c3: red の線は電源` は字が `red の線は電源` のまま赤くない。
`source` と `parts` にも色を書ける。

- **向き**は `r90` / `r180` / `r270` / `mirror` で、部品と同じ語彙
  (`- text f6 blue r90: ここから電源`)。**書けるのは `text` だけ**。
- **回るのは指す穴のまわり。** 字の真ん中で回すと、指す先から離れていく。
- **`mirror` は字を裏返さない。** 鏡文字は読めないので、**指す穴の反対側へ
  移す**の意味にしてある (上に何かあって重なるときに下へ逃がすためのもの)。
- **見た目**は `large` (字を 1.4 倍に。breadboard の `large` と同じ比) と `bold` (太字) で、**書けるのは `text` だけ**
  (`- text p2 red large bold: IN 5V`)。どちらかを書いた字は**透かさず、縁を白に**する —
  ほかの注釈の字は穴が透けて見えるよう薄く置くが、目立たせたい字まで薄いと意図が図に出ない。
  同じ形の USB-C 基板が並ぶ図の `IN 5V` と `OUT 3.3V` のように、取り違えると壊れる所に使う
- **置き場**は `left` / `right` / `center` で、字を**穴の脇**か真上に置く (`- text n23 red large bold right: AD3 1+`)。
  `right` は穴の右 (字の左端が丸のすぐ外)、`left` は穴の左 (字の右端が丸のすぐ外)、`center` は穴の真ん中 (字の中心が穴の真上) で、
  どれも穴と同じ高さに並ぶ。丸 (`mark`) で囲んだ穴の名前を書くときに使う (脇に部品の線が通るときは、1 行ずらした穴を `center` で指す)。書かなければ穴の上に置く。**向き (`r90` など) とは一緒に書けない**

**基板の外の番地にも書ける** (`- text -a1: 上のレールへ`)。図のほうが場所を空けるので、
題に重なったり画布の外で切れたりしない。

注釈は**一番上に描く** — 指したものが下に隠れると印の意味が無くなる。

### 書き出し (`- source`)

`- source` はそのフェンスの中身を、囲みごと図の下に写す。**図だけを貼られた人が、
同じ図をもう一度出せる**ようにするためのもの。

- **番地は書かない。** フェンス全体は基板より高いのが普通で、基板に重ねると穴も
  部品も読めなくなる。置き場所は図の下の帯で、選べない
- **行番号は添えない。** 値打ちは見たまま書き写せることなので、番号が混ざると
  写したものが動かない
- 基板より横に長い書き出しでは、切らずに**画布のほうを広げる**
  (細い基板で `…` だらけにしない)
- 色を書かなければ**図の文字色に従う**。白黒 (`mono`) の図で書き出しだけが
  浮かないようにするため
- 長いフェンスは途中で切り、**切ったことを図に書く** (黙って落とさない)
- 2 つ書いても描くのは 1 つ。**残りは無視したとお知らせする**

### 部品表 (`- parts`)

`- parts` は**何を揃えればよいか**を図の下に出す。番地と値は図の中に散らばって
いるので、拾い集めるには図を目で追うしかない。**同じフェンスから出す**ので、
部品を足したのに表を直し忘れる、が起きない。

| 欄 | 出るもの |
| --- | --- |
| 部品 | 書いた ID (`R1`) |
| 種類 | 正式名。姿を書いてあれば添える (`capacitor/ceramic`)。セラミックフィルタの型番 (`sip3` + `SFU455B`) は `セラミックフィルター` |
| 値 | 書いた値 (`10k` / `NE555`)。機器は名札 (`電池 3V`) |
| 色・記号 | 抵抗は**カラーコードを実際の色の四角**で (`10k` → 茶・黒・橙・茶)。コンデンサは**胴に刷ってある 3 桁の記号** (`100n` → `104`、`1u` → `105`) |

- **抵抗の色は実際の色の四角で出す** (字の `茶黒橙茶` は出さない)。実物を選ぶときに
  見るのは帯の色そのもので、図の帯は小さくて読みにくい。白と黒も地と分かるよう細い縁を付ける。
  (値として読めない抵抗は、行ごと断るので表にも出ない)
- **コンデンサの記号は電解には出さない** (電解は値をそのまま刷る)。10pF 未満など
  3 桁で書けない値も出さない
- **基板も 1 行で出る** (見出しのすぐ下、`基板` / `perfboard`)。値は呼び名・穴数・厚さ・基材の順 (`5x7cm (18×24 穴) 1.6mm FR-4`、穴数で書いた基板は `25×15 穴 1.6mm FR-4`)。書かなかった厚さと基材も既定のまま出す。色は載せない
- 基板の外の機器も並べる。**盤面に載らないだけで、揃えるものには変わりない**
- **名前の順に並べる** (数字は数として: `R2` の次は `R10`。機器も同じ並びに入る)。表から部品を探しやすくするため
- 置き場所は書き出しと同じ図の下の帯で、選べない (`- source` を書けば
  **部品表が上、書き出しが下**)
- 2 つ書いても描くのは 1 つ。**残りは無視したとお知らせする**

## 見た目 (`style:`)

テーマの名前 1 つだけなら、そのまま書ける。

```yaml
style: dark
```

項目で書くこともできる。

```yaml
style:
  theme: mono
  width: 720
  debug: off
  stamp: on
  check: off
  back: on
  labels:
    case: upper
    sides: left top
```

| 項目 | 書くもの | 既定 |
| --- | --- | --- |
| `theme` | `light` / `dark` / `mono` | `light` |
| `width` | 図の幅 (120〜4000) | 基板の大きさなり |
| `debug` | お知らせを帯に出すか | `on` |
| `stamp` | 版を図の右下に刻むか | `on` |
| `check` | ERC と当たり判定を掛けるか | `on` |
| `back` | 半田面 (裏返した基板) も描くか | `off` |
| `labels` | 基板の外の名前の付け方 (`case` / `sides`) | `upper` / `left top` |

**配色だけがテーマで動く。** 穴や字の寸法は 3 つとも同じで、同じフェンスを別の
テーマで出しても部品の位置も線の通り道も動かない。`mono` は白黒で刷る資料向けで、
**色で意味を持たせない**。

**`mono` では色が網と線の型に移る。** 配線の色・LED の色・抵抗のカラーコードは
実物の色なのでテーマでは動かないが、白黒の図にそこだけ色が残ると `mono` の
値打ちが消える。落とすと今度は「同じ色の線は同じ網」が読めなくなるので、
色ごとに**線の型** (`stroke-dasharray`) と**網** (`<pattern>`) を決めてある。

- 引き当てる**凡例が基板のすぐ下に出る**。並ぶのは**その図が使った色だけ**で、
  色を書かなければ凡例も出ない
- 見本は**線と網の両方**を出す。配線からも部品からも同じ表を引けるようにするため
- **黒は実線・塗りつぶし。** いちばん多く使う色 (GND) を素の形に置くと、
  網が付いた線だけが「色を書いた線」として目に立つ
- 抵抗の値は凡例からも読めるが、**部品表 (`- parts`) の色欄**のほうが速い
  (`10k` → `茶黒橙茶`)

`width` は書き出す画の大きさだけを変える (`viewBox` は動かない)。
`debug` と `stamp` と `check` は `on` / `off` で書く (`true` / `false` でも同じ)。

**`debug: off` で伏せられるのはお知らせだけ。** 読めなかった行はこの切り替えの
対象ではない — 伏せると「無かったこと」に化ける。

**`check: off` は伏せるのではなく、そもそも見ない。** `debug: off` が見つけたものを
帯に出さないだけなのに対し、こちらは検査を掛けないので、呼び出し側が受け取る
お知らせにも出てこない。回路の一部だけを描いた図など、**未結線が承知のうえ**の
ときに使う。図は 2 つとも同じで、変わるのは言うことだけ。
**読めなかった行はこの切り替えの対象ではない** (`debug` と同じ)。

### 基板の外の名前 (`labels:`)

行と列の名前は、**番地の綴りと同じ字**で出る。英字と数字のどちらが行かは
`board:` の `silk:` が決める ([英字と数字の振り方](#英字と数字の振り方-silk))。
`labels:` で選べるのは英字の大小 (`case`) だけで、既定は**大文字** — 基板のシルク
(秋月 C タイプの A・E・J・O) が大文字なので、そちらに合わせている。

**`row` / `col` は廃止した。** 印字だけを替えると、図の名前とフェンスの綴りが食い違う。
書くと断って `silk:` を案内する。

**名前を出す辺は `sides:` に空白で並べる** (`left` `right` `top` `bottom`)。
`all` で四辺、`none` で消す。**既定は左と上だけ** — 四辺に出すと、小さい基板では
名前のほうが基板より目立つ。大きい基板で端から数え直したいときに増やす。
出す辺には**余白を空ける**ので、右と下に出しても字が画布から切れない。

### 半田面 (`back:`)

**重ね順は手前から、半田点 → 配線 → 部品。** 半田面で手を動かすときに見るのは
半田付けする穴と、そこを渡るジャンパで、部品は基板の向こう側にある。部品は薄く
敷いて「どのランドがどの部品のピンか」だけを伝える。

`back: on` で、**裏返した基板**を図の下に足す。ユニバーサル基板は配線を裏で
半田付けするので、手を動かすときに見るのはそちら側になる。頭の中で裏返すのは
間違えやすい (1 番ピンの側を取り違えると、直すのに全部剥がすことになる)。

- **入れ替わるのは列だけ。** 基板を縦軸でひっくり返すので、行はそのまま
- **字は裏返さない** (鏡文字は読めない)
- 描くのは基板・穴・配線・部品。部品は基板の向こう側にあって実際には見えないが、
  **どのランドがどの部品のピンか**が分からないと半田付けできないので、透かして置く
- 基板の外の機器と注釈は表の図の話なので出てこない
- **既定は出さない** — 要るのは実際に半田付けするときだけで、図の高さが倍になる

## 複数の基板 (`sheets:`)

1 つのフェンスに基板を**何枚でも**並べられる (52 の docs/117)。`sheets:` を書かない図は
今までどおり 1 枚の図で、何も変わらない。

```yaml
title: 図01 LED 回路         # 外側の title: は各枚の題の頭に付く
board: 12x6          # 外側の board: style: は、枚が書かなかったときの既定
sheets:
  - name: 電源             # 枚の名前。図の題にもなる (図01 LED 回路・電源)
    # ここから先は 1 枚の図と同じ書き方
  - name: LED
links:
  - 電源.GND LED.GND
```

- 一番外側に書けるのは `title:` `sheets:` `links:` `board:` `style:` だけ。
  `parts:` や `wires:` は**枚の中**に書く (外に書くと、どの枚の物か決まらない)
- `sheets:` の下は `- ` で枚を並べる。枚の中の書き方は 1 枚の図と同じ。枚が `title:` を持てば、
  枚の名前から作る題より優先する
- 枚の名前 (`name:`) に空白と `.` は使えない。重ねられない。書かなければ `sheet1` `sheet2` …
- 描くときは枚ごとに今までの 1 枚の描き方で描き、**縦に左を揃えて積む**。枚の間に線は引かない
  (実物では基板の間を電線でつなぐ)
- `links:` は枚をまたぐ導通。`枚の名前.ネットの名前` を 2 つ以上並べると、**ネットリストでは 1 つのネット**になる。
  ネットの名前は `points:` に書いた名前か、名前を付けなかったネットの `N1` など
  (名前がわからないときは、わざと間違えて書くと言われる)
- ネットリストの名前は、枚をまたぐ前提で **`枚の名前.ネットの名前`** になる (どの枚にも `N1` があるため)。
  `links:` で併せたネットは、名前がそろっていればその名前 (`GND`)、違えば先頭に書いた名前
- 部品の名前 (`R1`) は図全体で 1 つ。2 つの枚に同じ名前があるとお知らせが出る
- 言われること (エラー・お知らせ・ERC) の行番号は**元のフェンスの行**。外側の `board:` `style:` を
  足した枚の中の誤りは、外側の行を指す
- **マップ (掴んで動かす編集) は `sheets:` の図では使えない**。図は描けて、`check` と `render` も通る
- 例: [../examples/12-sheets.md](../examples/12-sheets.md)

## ネットリスト

穴の導通と配線から導く。**全穴が独立している**ので、部品を挿しただけでは
何にもつながらず、ネットリストは書いた配線からだけ出る。

図05 のネットリストはこうなる。

```text
VCC : R1.1
GND : R1.2
```

ピンの名前は `部品名.番号` で、番号は書いた順。名前を付けていないネットは
`N1` `N2` と連番になる (`points:` の名前と重ならないように選ぶ)。

ネットリストは CLI の `check` / `render` が出す。プレビューには出ない。

## 言われること

**読めなかったところ**は、図の外の帯に出る。**行番号と、その行の中身と、
綴りを指す印**が付く。

**基板は必ず描く。** YAML が読めない行があっても、`board:` が書かれていなくても、
読めた所まで組んで返す。図が消えると、エディタで部品を置くことも動かすことも
できなくなるため。

基板が決まらないときに何で描いたかは、必ず帯で言う。

| 書き方 | どの基板で描くか | 帯に出るもの |
| --- | --- | --- |
| `board:` が無い | 既定の基板 (25x15) | `board: が要ります。…` |
| `board: elegoo-5x7` (読めない) | 既定の基板 (25x15) | 読めない理由と、`board: を読めないので、既定の板 (25x15) で描いています` |
| `board:` をマップで書き、`size:` は読めるが `color:` が読めない | **書いてある `size:` の基板** | 色の理由だけ |

**読めた所は捨てない** — 色が読めないだけで大きさまで捨てると、書いてある基板とは
別の大きさの図が、色の指摘だけを付けて黙って出る。

**ERC は帯の「検査 N」の釦の向こうに畳んである。** この基板は全穴が独立していて
繋ぎ忘れがピン 1 本ごとに出るので、組んでいる途中はほとんどが「まだつないでいない」に
なる。**帯が中間状態で埋まると、直す場所のある報告がそこに埋もれる。** 件数はいつも
出ていて、押すと広がる。もう一度押すと畳む (押した状態はフェンスには書かない)。

**当たり判定 (胴の重なり) は帯に残る。** 置いたその場で直す間違いで、中間状態として
当たり前に出るものではない。`style: check: off` を書くと、どちらも掛からない。

**図の下の帯 (プレビュー) と CLI は今までどおり**、ERC もお知らせも並べて出す。

**お知らせ**は「読めてはいるが、そのとおりに組むと動かない」もの。
帯には読めなかったものが先に並ぶ (お知らせはピン 1 本につき 1 件出るので、
行順のままだと本物のエラーが打ち切りで消える)。

お知らせに出るのは 8 つ。

| 見るもの | なぜ |
| --- | --- |
| どこにもつながっていないピン | 全穴独立なので、挿しただけでは何にもつながらない (機器のピンも同じ) |
| 配線で短絡した部品 | 抵抗を入れたつもりが線でまたいでいた、という取り違え |
| 部品のピンを 1 つもつないでいない配線 | ネットリストから落ちるので、言わないと黙って消える |
| 胴の重なり | ピンの穴が別でも胴は重なる。実物では両方を挿せない |
| ピンの間隔が狭すぎる | 胴の両端からピンが出る部品は、胴より狭い間隔に入らない |
| 機器が基板の幅に収まらない | 帯からはみ出した箱は黙って切れる。切れた図は間違いに見えない |
| 機器どうしを結ぶ配線に書いた色 | 基板に触れないので線が無く、図に出ない。黙って消すと効かない指定を書き続ける |
| 番地で置いた機器の箱が基板に被る | 箱の左上が番地なので、`-a` や `0` に置くと基板の縁と列の名前を隠す。避けられる番地を添える |

**読めなかったところがあるうちは、うち上の 5 つを見ない。** 落ちた配線を勘定に
入れないまま「つながっていません」と言うと、書いた配線について書き忘れを
指摘することになる。見ていないことは黙らずに言う。

## 上限

他人の書いたノートを描く前提なので、必ず頭を打たせる。

| もの | 上限 |
| --- | --- |
| 基板の大きさ | 120 列 × 120 行 |
| 部品 | 200 個 |
| 配線 | 500 本 |
| `points:` の名前 | 100 個 |
| `unused:` のピン | 200 個 |
| `shorted:` の部品 | 50 個 |
| 機器 1 つのピン | 64 本 (名前は 24 字) |
| 注釈 | 200 個 (1 つ 60 字) |
| 名前の長さ | 32 字 |
| 値・題の長さ | 60 字 |
| 行の名前 / 列の番号 | 4 字 / 4 桁 |

行の名前に上限があるのは**止まらなくなるから**。無制限に受けると行番号が
桁あふれして `Infinity` になり、名前を作る桁下げが終わらない。
