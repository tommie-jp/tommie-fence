# Perfboard Fence

[English](README.md) | [日本語](README.ja.md)

Markdown の ` ```perfboard ` フェンス (YAML) を、ユニバーサル基板の実体配線図として
プレビューする VS Code 拡張。

**まだ板・穴・2 本足の部品までです。** 配線とネットリストはこれからです。

## 何を目指しているか

ブレッドボードで試した回路を、**自分で決めた配置で**ユニバーサル基板へ移す。
そのときの図と手順書を、実験ノートの中にそのまま書けるようにする。

```yaml
board: 28x18
parts:
  R1: resistor b3 b7 10k
  D1: led c5 c9
wires:
  - b7 -- c5
```

- 位置は**番地** (`b3` = b 行の 3 列目)。座標のペアではないので、差分が
  意味を持ち、LLM に書かせても崩れにくい。行の名前は表計算と同じ数え方で
  伸びるので、26 行を超える板でも `aa` `ab` と続けて読める
- **配線は手で引く**。自動ルータは入れない — どこに何を置くかを人が決める
  用途に合わないため。書かれたとおりに描くので、はんだ付けの手順書になる
- 導出するのは**ネットリスト**と**エラー**。ユニバーサル基板は全穴が独立して
  いるので、繋ぎ忘れが図の上で沈黙する。ここは機械に見張らせる

## 姉妹パッケージとの違い

| | 描くもの | 穴の導通 |
| --- | --- | --- |
| [circuit-fence](../circuit-fence/) | 回路図 | — |
| [breadboard-fence](../breadboard-fence/) | ブレッドボード実体配線図 | 列の 5 穴が内部でつながる |
| perfboard-fence | ユニバーサル基板 | **全穴が独立**。導通は配線でしか生まれない |

言語は別、作法は同じ (YAML をホストにしたフェンス、番地で書く位置、
Markdown の行番号とその行の中身で返るエラー)。

## いまできること

| | 状態 |
| --- | --- |
| ` ```perfboard ` フェンスの認識 | できる |
| 空のフェンス・YAML の構文エラーを行番号つきで返す | できる |
| 知らないキーを名指す | できる |
| **板と穴を描く** (`board: 28x18`) | できる |
| **番地** (`b3`、26 行を超えたら `aa3`) | できる |
| **2 本足の部品を置く** (抵抗・LED・コンデンサなど 17 種) | できる |
| **抵抗のカラーコード**と LED の色 | できる |
| 3 本足・DIP・SIP | **これから** |
| 配線・ネットリスト・ERC | **これから** |

板の大きさは**列 × 行**で書きます (板が「72×47.5mm」と長辺 × 短辺で
売られているのと同じ順)。名前の付いた板 (`akizuki-c` など) はまだありません —
秋月の商品ページは寸法とピッチしか書いておらず、穴数の一次情報が無いので、
実物で数えるまでは書く人が自分の板を見て書きます。

## 開発

リポジトリ直下から回す (npm workspaces)。

```bash
npm run check --workspace=perfboard-fence   # 型チェック + テスト
npm run build --workspace=perfboard-fence   # dist/ を作る
./doBuild.sh perfboard-fence                # .vsix を作って VS Code に入れ直す
```
