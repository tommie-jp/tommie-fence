# Perfboard Fence

[English](README.md) | [日本語](README.ja.md)

Markdown の ` ```perfboard ` フェンス (YAML) を、ユニバーサル基板の実体配線図として
プレビューする VS Code 拡張。

**まだ 3 本足・DIP は置けません。** 2 本足の部品なら、置いて・つないで・
検証して・書き出すところまで一通り動きます。

## 何を目指しているか

ブレッドボードで試した回路を、**自分で決めた配置で**ユニバーサル基板へ移す。
そのときの図と手順書を、実験ノートの中にそのまま書けるようにする。

```yaml
board: akizuki-c
parts:
  R1: resistor b3 b7 10k
  D1: led c5 c9
wires:
  - b7 -- c5
```

- 位置は**番地** (`b3` = b 行の 3 列目)。座標のペアではないので、差分が
  意味を持ち、LLM に書かせても崩れにくい。行の名前は表計算と同じ数え方で
  伸びるので、26 行を超える板でも `aa` `ab` と続けて読める
- **配線は手で引く**。自動ルータは入れない — どこに何を置くかを人が決める
  用途に合わないため。書かれたとおりに描くので、はんだ付けの手順書になる
- 導出するのは**ネットリスト**と**エラー**。ユニバーサル基板は全穴が独立して
  いるので、繋ぎ忘れが図の上で沈黙する。そこは ERC が見張る — どこにも
  つながっていない足を、行番号つきで名指す

## 姉妹パッケージとの違い

| | 描くもの | 穴の導通 |
| --- | --- | --- |
| [circuit-fence](../circuit-fence/) | 回路図 | — |
| [breadboard-fence](../breadboard-fence/) | ブレッドボード実体配線図 | 列の 5 穴が内部でつながる |
| perfboard-fence | ユニバーサル基板 | **全穴が独立**。導通は配線でしか生まれない |

言語は別、作法は同じ (YAML をホストにしたフェンス、番地で書く位置、
Markdown の行番号とその行の中身で返るエラー)。

## いまできること

| | 状態 |
| --- | --- |
| ` ```perfboard ` フェンスの認識 | できる |
| 空のフェンス・YAML の構文エラーを行番号つきで返す | できる |
| 知らないキーを名指す | できる |
| **板と穴を描く** (`board: 25x15` / `board: akizuki-c`) | できる |
| **番地** (`b3`、26 行を超えたら `aa3`) | できる |
| **2 本足の部品を置く** (抵抗・LED・コンデンサなど 17 種) | できる |
| **抵抗のカラーコード**と LED の色 | できる |
| **配線を引く** (`- b7 -- c5 red`) | できる |
| **ネットリストを導く** | できる |
| **`points:` で穴に名前を付ける** | できる |
| **ERC** (未結線の足・短絡した部品・空中配線) | できる |
| **当たり判定** (胴の重なり) と足の間隔 | できる |
| **図の題** (`title:`) | できる |
| **CLI** (`render` / `check`) | できる |
| 3 本足・DIP・SIP | **これから** |
| `device` (基板外の機器)・`notes:`・`style:` | **これから** |

板は**穴数**か**名前**で書きます。穴数は列 × 行 (板が「72×47mm」と
長辺 × 短辺で売られているのと同じ順)。名前は `akizuki-b` / `akizuki-c` /
`akizuki-d` の 3 つで、`72x47mm` や `7.2x4.7cm` と実寸で書いても同じ板が出ます。

**実寸から穴数は計算していません。** 縁の余白は板ごとにも辺ごとにも違い、
取付穴がそこに入るので、ミリを 2.54 で割っても穴数は出ません。名前で引けるのは
商品写真から数えた板だけです。数えていない大きさを書くと、近い板を挙げて返します。

## 書き方

文法は [docs/01-syntax.md](docs/01-syntax.md)、回路 1 つずつの例は
[examples/](examples/README.md)。

## CLI

```bash
node dist/cli.cjs render examples --out examples/out   # 図を書き出す
node dist/cli.cjs check examples                       # 書かずに検証だけ
```

`check` はネットリストと言うことだけを出す。読めない行が 1 つでもあれば
終了コードは 1 になるので、CI や LLM の自己修正ループから回せる。

## 開発

リポジトリ直下から回す (npm workspaces)。

```bash
npm run check --workspace=perfboard-fence      # 型チェック + テスト
npm run examples --workspace=perfboard-fence   # 図を作り直す
./doBuild.sh perfboard-fence                   # .vsix を作って VS Code に入れ直す
```
