# プロジェクト指示 (graph-fence)

Markdown の ` ```graph ` フェンスを教科書の x-y グラフとして描くライブラリ + CLI。
横断の作法は[リポジトリ直下の CLAUDE.md](../../CLAUDE.md)、
**このパッケージについてはここが正**。起こした経緯と決めは
`~/52-tommie-fence/docs/92`・`96`・`98` にある (private)。

## この図の物理 (設計が計器の 3 つと分かれる理由)

**図の中に部品も板も計器も無い。** 描くのは x の関数と点で、そこから次が全部出てくる。

- **ネットリストも ERC もマップ (エディタの殻) も無い** (scope・spectrum・vna と同じ)。拡張には
  `FenceEditor` を渡さず、Problems に出す口 (`problemsOf`) だけを渡す
- **計器の画面ではない。** 計器の語 (div・トリガ・RBW・S21) を持たず、軸の名前と単位は書き手が決める。
  画面を見せる題は scope・spectrum・vna、値を集めて描く題が graph
- **単位は意味を持たない字** (`mA` `dB` `℃`) — 枠を分ける鍵と、名札・読み値に刷る字だけ。
  単位の違う線は横軸を共有して縦に積んだ枠に置く (vna の「単位ごとの枠」と同じ考え)
- 線の元は 3 通り: **式** (理想・破線)、**点列** (予想・破線)、**実測** (`data:` の CSV。○ で打ち、線で結ばない)

## 約束

1. **core はファイルを開かない**。`data:` は宿主が `DataSource` で渡す (CLI は `.md`
   の隣、拡張は `env.currentDocument` の隣)。**名前は `DATA_NAME` 1 か所で絞る**
   (`/` も `..` も通さない)。宿主の読み口は fence-kit の `readNeighbor`
2. **エスケープが唯一の防御**。図と帯に載る字は `escapeMarkup`、入力の断片を報告に載せる入口は
   `safeToken` だけ。CSV の見出しの字は `dropInvisible` を通してから言うことに載せる。`#` の頭書きは描かない
3. **式は自前の再帰下降で読み、`eval` も `Function` も使わない** (`model/expr.ts`)。
   関数の表は `Object.hasOwn` で引く (`constructor` などに届かない)。字数・深さに上限
4. **読めなかったところは図の外に出す**。**枠は必ず描く** (空でも。54)。
   `data:` が読めないのはお知らせ (理想だけで図は出る)
5. **SVG に `NaN` / `Infinity` を書かない**。描けない値の点は抜き、枠の外へ出る所は線を切る
   (縁に寄せると無い値を在るように見せる)
6. **上限を置く** (`limits.ts`)。線・点・式・枠・注釈・mark・対数の桁・ファイルの大きさ・行・列
   (**列は配列を確保する前に断る**)
7. **黙って別の意味に読まない** (直下の CLAUDE.md の文法の方針 1)。軸と違う単位は断る
   (`0.0176A` を mA の軸で読まない)、`2x` は断る (`2*x`)、範囲の `2k-32k` は断る (`2k..32k`)。
   数の接頭辞は SI のとおり大文字小文字を区別する (`m` と `M`)
8. **理想も実測も同じ読み方** (`model/lines.ts` の `valueAt`)。式はその x で計算、点列は前後の間を直線
   (対数の軸なら log x)、実測は一番近い点
9. **補った既定のうち図の中身を決める物は言う** (`x:` と `lines:` が無いとき、線の無い `y:`、
   対数の枠で落とした 0 以下の点)。見た目の既定 (範囲・目盛・テーマ) は名札と目盛に出るので言わない
