# 読めているが、そのままだと違って出るもの

読めなかったわけではないので図は描ける。ただ、書いた人の思ったとおりには
出ないことがある。こういうものは**お知らせ**として、行番号つきで図の下に出る
(エラーとは分けてある)。

**この例もわざと引っかけてある。**

写しの先頭に付けた数字は、分かりやすくするために添えた行番号。
**ソースに行番号はない**。

## `--` でピンへ引くと斜めに入る

ピンは記号ごとに決まった位置にあって格子の上に無い。`--` は 2 点を
まっすぐ結ぶので、記号の中心線に乗っていないピンへ引くと斜めに入る。

```circuit
title: 図01 ピンへ斜めに入る
parts:
  U1: opamp 5,3
wires:
  - U1.+ -- 3,3
```

書いたのはこれ。

```text
18 title: 図01 ピンへ斜めに入る
19 parts:
20   U1: opamp 5,3
21 wires:
22   - U1.+ -- 3,3
```

帯にはこう出る。

```text
circuit: 22 行目: U1.+ へ -- で引くと斜めに入ります (|- か -| なら直角に入ります)
```

`|-` なら先に縦、それから横に入るので、回路図らしく直角に入る。

中心線に出るピン (トランジスタの C・E、オペアンプの out など) へ、
その軸に揃った番地から引くときは何も言わない。`U1.out -- 7,3` はまっすぐ引ける。

## 色が YAML のコメントとして消える

`#` から先は YAML のコメントなので、`ink-color: #333` は値が空のまま届く。
こちらは読めなかったので**エラー**のほう。

```circuit
title: 図02 色が YAML のコメントで消える
parts:
  R1: resistor 1,1 3,1
style:
  ink-color: #333
```

書いたのはこれ。

```text
52 title: 図02 色が YAML のコメントで消える
53 parts:
54   R1: resistor 1,1 3,1
55 style:
56   ink-color: #333
```

帯にはこう出る。

```text
circuit: 56 行目: style の ink-color は色として読めません (# から先は YAML のコメントになります。"#333" のように "…" で囲みます)
```

`"#333"` と囲めば通る。
