# 部品と節点を動かす

図を見ながら別の番地へ移すための操作。**番地で位置を書く**フェンスなので、
「動かす」は行の中の番地の綴りを差し替えるだけで済む。

**操作は 3 つのフェンスで同じ** (KiCad 流。鍵・手つき・画面の配置)。
共通の操作は fence-kit の
[docs/01-図を掴んで動かす.md](../../fence-kit/docs/01-図を掴んで動かす.md)
にまとめてある。ここに書くのは **circuit での違い**と、マップが図ではなく
升目であることから来る事情。

## 掴む物は 2 つ

**部品**と**節点**では、動かした結果が違う。

| 掴む物 | 動くもの | 接続 |
| --- | --- | --- |
| 部品 (`M` かドラッグ) | その部品だけ | 変わる (離れた / つながった接続を動かしたあとに出す) |
| 節点 (`G`) | その交点に来ているもの全部 | 保たれる |

掴む物が違えば意味も違うので、**同じ操作に混ぜない**。「接続を保ったまま
部品を動かす」を既定にしていないのはこのため — 端子を連立で置き換えると、
`R1 a1 a2` を右へ 1 つずらしたときに配線 `a2 -- a3` が `a3 -- a3` (長さ 0) に
なるような縮退が起きて、1 部品の移動が図全体へ予測できない形で波及する。

## 4 つの入口

| 入口 | 何をするか |
| --- | --- |
| **circuit Editor** (タブの頭の開き方の一覧) | `.md` のタブそのものをマップにする |
| `Circuit Fence: 図を掴んで動かす (マップ)` | 同じマップを、升目のパネルとして横に開く |
| `Circuit Fence: 部品を動かす` | 部品を選び、移動先の番地を打つ |
| `Circuit Fence: 節点を動かす` | 節点を選び、移動先の番地を打つ |

コマンドの 3 つは Markdown のエディタで、**circuit フェンスの中にカーソルを
置いてから**実行する。circuit Editor にはカーソルが要らない (下の節)。

## タブそのものをマップにする (circuit Editor)

`.md` のタブの頭にある開き方の一覧 (`Text Editor ▾`) で **circuit Editor** を
選ぶと、そのタブがマップになる (`View: Reopen Editor With...` でも同じ)。
`.md` を開いたときの既定は今までどおりテキストエディタで、こちらからは
変えない — 既定にしたければ VS Code の「Set Default for '*.md'」で選ぶ。

中身は横に開くパネルと同じ。違いは 3 つ。

- **文書が固定される。** タブは 1 つの文書のものなので、別の文書のフェンスへは
  乗り換えない。同じ文書の中なら、隣に開いたテキストエディタのカーソルに従う
- **フェンスが複数あれば、頭の一覧で選ぶ。** タブにはカーソルが無いので、
  最初は文書の最初のフェンスから始まる。フェンスが 1 つなら一覧は出ない。
  フェンスが無い文書では、その旨だけが出る。選んだフェンスは、**カーソルが
  別のフェンスへ入るまで守る** (隣のテキストエディタで打っただけで、
  選んだフェンスがカーソルの側へ戻ってしまわないように)
- **戻す・やり直すは VS Code のもの。** タブの文書へ VS Code の undo が届くので、
  `Ctrl+Z` と頭のボタンはそのまま VS Code の undo / redo を呼ぶ (パネルのような
  自前の履歴は持たない。手で書き換えた分も一緒に戻る)

図を見るには、同じ文書を Markdown プレビューで隣に開く。書き換えは
テキストエディタにもプレビューにもすぐ届く (文書は普通の文書のままで、
保存も、閉じて開き直したときの復元も VS Code が持つ)。

## マップは升目 (回路図に寄せた記号)

パネルの升目は、図ではなく**フェンスのモデルから直に描いたもの**。
図そのものを掴めないのは、描き上がった SVG に番地の手がかりが残らないため。
升目なら位置合わせの問題がそもそも無い。

**部品の形と配線もそのまま描く。** 形は**回路図の記号になるべく寄せてある** —
抵抗は折れ線、トランジスタはベースの棒と 2 本の足、論理ゲートは背の形
(AND は平ら、OR は反り、XOR は反りがもう 1 本) で出る。
細部だけが違うもの (ショットキーとダイオード、npn と pnp) は同じ形に落ち、
その差は図のほうが言う。DIP のような IC は名前を入れた箱で出る
(箱がその部品の正しい姿でもある)。

記号の正確さは図 (TeX) のほうが正しい。ここは**どれがどこにいて、どこが
つながっているかを掴むためのもの**。

配線のうち、ピンで書いた端 (`U1.2 -- a5`) は**破線**で出る。足の正しい位置は
記号の形から決まるので、こちらからは分からない (下の「節点を動かす」の
限界と同じ根)。

多端子部品からは**足が出る** (トランジスタなら `B` `C` `E`)。足の名前は
文法リファレンスの代表の綴りと同じ字で、**出る辺は向きに合わせて回る** —
`r90` と書いた記号はマップの上でも横を向く。`ground` は足を持たないので、
記号そのものを回して見せる。

注釈は指した升の角に**札**で出る。`text` は書いた字が札に載り、字に合わせて
札が伸びる。長い注釈は `…` で切るので、**全文は札に乗せると出る**。

**DIP とトランスの向きは升目に出ない。** 足が記号の中心線に乗っていないので、
どの辺から出るかが決まらない (回した結果は図のほうで確かめる)。

隠れても (パネルを同じタブグループに入れた配置でも) そのまま掴める。
別のフェンスに乗り換えるときは、そのフェンスの中にカーソルを置く。

**図は書き換えのあと数秒で描き直る** — TeX からの描画は 1 図 1 秒前後かかる
ので、升目は先に動き、図があとから追いつく。

## 置く (この升目での番地)

`A` で種類を選ぶと、押した交点を 1 つ送るだけでよい。

- **2 端子は右へ 2 升** (`c1` → `c1 c3`)。ドラッグすれば間隔を選べる。
  1 端子・多端子は押した交点 1 つ
- 代表 12 種はアイコン、残りは検索欄から。**種類名・略記・和名**のどれでも
  引ける (`resistor` / `r` / `抵抗`)
- **ID は接頭辞ごとに最小の未使用番号。** 接頭辞は docs の例に合わせてある
  (`R` 抵抗、`C` コンデンサ、`Q` トランジスタ…)。同じ接頭辞を分け合う種類は
  続き番号になる (`P1` が lamp なら potentiometer は `P2`)
- **`port` / `vcc` / `vee` は既定の名前で置く** (`IN` / `VCC` / `VEE`)。ID が
  そのまま図に出てネットの名前にもなるが、窓で止めずに置いて欄で直す
  (KiCad が `#PWR?` で置いてから直させるのと同じ)。`IN` が使われていれば `IN2`。
  `VCC` は何か所にあっても同じ節点なので 2 つ目も `VCC` —
  **同じ名前をもう一度置ける**のは回路図の書き方そのもの
- **同じ名前が 2 つ以上あっても、掴んだものが 1 つに決まる。** マップは部品を
  名前ではなく**名札**で指す — 名前が重なっていなければ名前そのもの、重なった
  ときだけ書いた順の 2 つ目から `VCC#2` `VCC#3` と数える (`core/edit/handles.ts`)。
  名札はマップの中だけの綴りで、フェンスにも図にも出ず、人に見せる字は名前のまま。
  **名前を変える・消すときは、その 1 つだけ**を書き換える
- `parts:` が無ければ鍵ごと作る (`wires:` より前に置く)。書けない組み合わせ
  (使えない ID、知らない種類、格子の外) は**ゴーストが赤くなり、押す前に**断る

## 動く量

**最初の番地がアンカー**で、部品は形を保ったまま平行移動する。

```yaml
R1: resistor a1 a3 10k
```

`R1` を `b1` へ動かすと `resistor b1 b3 10k` になる。値やラベルは触らない。

格子の外へ出る移動は断る (a〜z の 26 行、1〜99 列)。
交点の間の番地 (`a_1.5`) を持つ部品は升目に載らないので、マップには出ない
(コマンドからは動かせる)。

## 接続が変わったら教える

**動かす前に止めない。** 移動の前後でネットリストを比べ、
**離れた接続と、つながった接続を動かしたあとに並べて出す**
(マップは状態行、コマンドは通知)。気に入らなければ戻せる (下の節)。

同じ番地に 2 つの部品が来るのは、この文法では**接続**。禁止ではなく
「つながった」というお知らせとして出る。

## 読めなかったところを帯に出す

マップの下に、**読めなかった行とお知らせ**が並ぶ。中身は図の下の帯と同じ
だが、あちらは**プレビューにしか出ない** — 掴んで動かしている間はプレビューが
隠れていることが多く、そこで足した部品や配線の間違いに気づく手立てが
無かった。編集はどれも間違いを生むので、直す場所を編集する場所と同じ窓に出す。

- **1 行を押すと、エディタでその行が光る。** 書き換えはしない — 直すのは
  書き手の仕事で、こちらは場所を指すだけ。行の分からないものは押せない。
  その文書のテキストエディタが 1 つも開いていなければ (タブそのものが
  マップのとき)、横に開いてから光らせる
- 行番号は Markdown の行 (フェンスの中の行ではない)。読めなかった行の中身も
  一緒に出て、綴りの当たっているところに印が付く
- **読めなかった行に書かれた部品と配線は、マップの上でも赤くなる** —
  行番号だけでは、どの記号のことか字と突き合わせないと分からない
- お知らせ (読めてはいるが、思ったとおりには出ないもの) は別の色で並び、
  絵には印を付けない (同じ赤で囲むと間違いに見える)。`style: debug: off` で
  伏せられるのはこちらだけで、読めなかった行は伏せられない
- 帯が伸びてマップを押し出さないよう、並ぶのは 12 件まで (残りは件数だけ)

## 消す・回す (この文法での書き換え)

- **消すのは行ごと。** 1 部品 = 1 行、1 配線 = 1 本の経路という文法の読みと
  揃える (光る単位・帯が指す単位とも同じ)。部品を消すと**足を指す配線も
  一緒に**消え、その本数を状態行に出す (`Q1.b -- a3` は Q1 が居なくなると
  読めない)。`parts:` / `wires:` の最後の 1 つを消したときは鍵ごと消す
  (空の鍵は読めない)
- **掴んだ物によって書き換えが変わる。** 使う人にとっては「回す」(`R`)
  「裏返す」(`X`) の 1 つの操作なので、違いはこちらで吸収する:
  - **2 端子部品** — 向きは番地の順そのもの。回すのはもう一方の端をアンカー
    (先に書いた端) の周りに 90 度動かすこと、裏返すのは両端の入れ替え。
    **同じ 2 つの升を使う**ので、裏返してもつながりは変わらず、極性のある部品
    (ダイオード・電解コンデンサ) の向きだけが変わる。格子の外へ出る回転は断る
  - **多端子部品と `ground`** — 1 つの番地に置くので番地では回せない。
    向きの語 (`r90` / `mirror`) を書き換える。4 回で一周したら語を消す
- **向きを書けない記号は理由を添えて断る** (`port` / `vcc` / `vee` は上下が
  その記号の意味、DIP は裏返すと足番号が鏡文字、トランスは回すと巻線と鉄心が
  ばらける)。断る文面は文法側と同じもの — 同じことを 2 通りの言い方で断ると、
  書いた人はどちらが本当か決められない
- 配線は**線にカーソルを置いて `Delete`** (見える線は細いので、太い透明な線を
  重ねてある)
- **フロー形式 (`parts: {…}` / `wires: [...]`) は断る。** 行が部品 1 つに
  対応しないので、行ごと消すと鍵まで消える。手で消す

## 配線を引く

`W` で、交点をクリック → 交点をクリック (ドラッグでも可)。`wires:` に 1 行増える。

- 既定は `--` (まっすぐ)。**`Shift` を押しながら終わりをクリック**すると `-|`
  (先に横、それから縦)。`|-` は手で書く。折れの綴りを持つのは 3 つのフェンスの
  うち circuit だけ
- 引く先の `wires:` が無ければ**鍵ごと**作る。ある場合は最後の配線の次の行に
  足すので、書いた順がそのまま並ぶ
- **端は交点だけ。** 足 (`Q1.b`) を指す配線は手で書く — 足の位置は記号ごとに
  決まっていて、マップにはまだ把手が出ていない
- 書き方 (字下げ) は既にある行に合わせる。フロー形式 (`wires: [...]`) には
  足せないので断る (行が 1 本に対応しない)

## 欄で直す (名前・種類・値・ラベル)

部品を選ぶと、左に**その 1 行の欄**が出る。**1 部品 = 1 行**の文法
なので、欄はその行の綴りとそのまま 1 対 1 になる。

| 欄 | 書き換わるところ |
| --- | --- |
| 名前 | 鍵 (`R1:`)、配線の足 (`R1.b`)、注釈の指し先 (`circle R1`) |
| 種類 | 鍵の次の綴り。端子の数が変わる種類には差し替えられない |
| 値 | 番地のうしろ。空にすると消える |
| ラベル | `l=字`。空にすると消える。2 端子だけ |

- **`Enter` か、欄を離れたときに当たる。** `E` (かダブルクリック) で名前の欄へ飛ぶ
- その部品に書けない欄は灰色になる (1 端子に値は書けない、多端子に `l=` は
  無い — 文法にその場所が無い)
- 名前は**どれか 1 つでも綴りとして取り出せなければ断る**。半分だけ書き換えると
  残ったほうが「そんな部品はない」になるため
- 種類は打つと候補が出る (パレットと同じ表から)

## 戻す・やり直す

上の**「元に戻す」「やり直す」**、または `Ctrl+Z` / `Ctrl+Shift+Z`。

タブそのものがマップ (circuit Editor) のときは、これは VS Code の undo そのもの。
横に開いたパネルでは、フォーカスがあると VS Code の `Ctrl+Z` がエディタに
届かないので、パネルが自分で覚えている。覚えるのは**マップでの書き換えだけ**で、
コマンドから動かしたぶんはエディタの `Ctrl+Z` が効く。

パネルが覚えているのは**フェンスの本文そのもの** (前と後ろの姿) で、桁では
ない。部品や配線を足す・消すで行がずれても照合が立つ。字下げも行末の空白も
文書から読んだまま持つので、戻すと元の姿がそのまま返る。

**そのフェンスを手で書き換えていると戻せない。** 本文を丸ごと書き戻すので、
当てると手で書いた分まで消えてしまう。触っていない行の直しでも断る
(そこだけ戻したいときはエディタの `Ctrl+Z` を使う)。

## 書き換え方

**YAML を組み直さない。** 行の中の番地の綴りだけを差し替える。
手書きのコメント・整形・並び順がそのまま残る。

`points:` で名前を付けた節点をそのまま端子に書いていた部品を動かすと、
**その端子は新しい番地のリテラルに変わる** (`points:` の側は触らない)。
名前の節点から離れることは、上の接続の変化に出る。

## 節点を動かす

その交点に来ているものを丸ごと運ぶので、**接続は保たれる**。

`points:` で名前が付いていれば、直すのは**普通はその行き先の 1 行だけ**。

```yaml
points:
  fb: c3
parts:
  R2: resistor fb d3 1k
  R3: resistor fb c5 10k
```

`fb` の節点を `c4` へ動かすと `fb: c4` の 1 行だけが変わり、`R2` と `R3` は
綴りを変えずに付いてくる。**これが `points:` の存在理由**そのもので、
番地を 3 か所に書いていると 1 か所の直し忘れに気づけない。
同じ番地を生の綴りでも書いていたら、そこも一緒に運ぶ — 置いていくと
接続が切れて、「丸ごと運ぶ」の約束が破れる。

名前が無ければ、その番地を書いている場所を全部書き換える。見るのは
**`parts:` と `wires:` の行の端子だけ** — `title:` や `notes:` や `style:` に
番地に見える字があっても触らない。`circle C1 red` の `C1` は部品の名前とも
番地 `c1` とも読めるので、綴りからは書いた側の意図を判別できない。
部品の名前 (`C1:` の鍵) も変えない。

**縮退は断る。** 動かした先に自分のもう一方の端がある部品や配線は長さ 0 になり、
図から消えてネットリストでは短絡になる。その組み合わせは動かす前に名指して断り、
先に部品のほうを動かすよう返す。

ただし見られるのは**番地で書いた端**だけ。ピンで書いた端 (`U1.2 -- a5` の
`U1.2`) の位置は TeX が部品の形から決めるので、こちらからは見えない —
ピンの真上の交点へ節点を寄せると長さ 0 の配線ができ得る (描き直った図で
気づく。書き換え自体は正しく、戻せば元に戻る)。

寄せた先に別の端が来ているときは、部品を動かすときと同じく
**つながった接続を動かしたあとに出す** (同じ番地 = 接続なので、禁止ではない)。
