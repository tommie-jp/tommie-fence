# プロジェクト指示 (circuit-fence)

Markdown の ` ```circuit ` フェンス (YAML) を回路図としてレンダリングする
VS Code 拡張機能。全体像は [README.md](README.md)、
文法は [docs/01-syntax.md](docs/01-syntax.md)。

## このプロジェクトの存在理由

回路図をテキストで描く手段自体は枯れている (CircuiTikZ / Schemdraw / Lcapy)。
**争点は描画品質ではなく、次の 2 点だけ**。ここを外すと作る意味がない。

1. **位置指定が番地で直接書けること** — Lcapy は制約グラフ + ダミーノードで
   間接的に配置を操る。図を直すとネットの節点名が動く。
2. **間違いが行番号で返ること** — Lcapy は配置が破綻すると Python の traceback で
   落ち、どの部品が原因かを出さない (公式ドキュメントも認めている)。
   LLM に書かせて自己修正ループを回す用途では、ここが一番効く。

分岐の黒丸の自動化と circuitikz 品質の図は **Lcapy が既に達成済み**なので、
売りにしない (必須装備として実装はする)。

## 設計上の約束

1. **コアは同期の純関数に保つ**: 「YAML → 検証 → 中間モデル → circuitikz TeX 生成」
   までは DOM・Node API・子プロセス・WASM を使わない (`src/core/`)。
   TeX → SVG の描画だけをガワ側 (`src/host/`) に置く。VS Code のプレビュー・CLI・
   サーバー側描画のどこから呼んでも同じ結果になることが、この設計の存在理由。
2. **実行時の依存を増やさない**: 依存は YAML パーサと描画エンジンだけ。
   スキーマ検証ライブラリは圧縮後 320KB 増えた経緯があるので手書きで通す。
3. **図に出る文字は必ずエスケープする**: プレビューは拡張が返した HTML を
   サニタイズしない。TeX に渡す文字列も同様に検証する
   (**ユーザー入力から任意の TeX を生成させない**)。値は `src/core/tex/escape.ts`
   の関門を必ず通し、許可した文字種だけを通す。
   書き出す `.tex` 向けに広げるのは**字種だけ**で、TeX の記法として読まれる字
   (`\` `$` `,` `=` など) はどちらの向けでも通さない。
4. **入力に上限を置く**: 他人の書いたノートを描く前提。部品数・配線数・
   ラベル長などの上限は `src/core/limits.ts` に集約する。
5. **エラーを握りつぶさない**: 読めなかった行は行番号つきで図の下の帯に出す。
   **検証は全部 YAML 層で終わらせ、TeX には検証済みの形しか渡さない**。
   それでも TeX が落ちたときのために、生成 TeX に `% line N` を埋めて
   TeX のエラー行を元の YAML 行番号へ引き戻す。
6. **生成する TeX は実機検証済みのパターンだけに限定する**: 記号は 1 つずつ
   実機に通してから `src/core/parts.ts` の表に載せる。フェンス側の TeX (WASM) は
   **フォントが無いと例外ではなくプロセスごと落ちる**ため、確かめるときは
   1 記号 = 1 プロセスで回す。**落ちなくても字形が壊れる記号がある**ので、
   通ったら図も見る。**通っても回路図の慣習と形が違う記号がある**ので、
   横に引いた図で見る。いま置き換えてあるのは 11 種類
   (`eC` / `op amp` / `ohmmeter` / `thRn`・`thRp` はフォントが無いため、
   `V` / `sV` / `sqV` / `vsourcetri` は中身が 90 度寝るため、
   `ammeter` / `voltmeter` は指針の矢が入るため、`transformer` は空芯のため。
   `vR` は矢の向きだけをフェンス側で返す。理由は parts.ts の表の頭)。
7. **フェンス向けと `.tex` 向けの違いは、フェンス側の制約が強いる分だけにする**:
   いまは 3 つ (日本語のフォント・siunitx・`op amp` の記号)。それ以外を変えると、
   プレビューで位置を確かめてから書き出す使い方が壊れる。
   **circuitikz の版差を吸収する指定はこの 3 つに入らない** (`vR` の矢の向き。
   フェンスは 1.0 で固定、手元の LaTeX はもっと新しい)。TeX の綴りは違うが
   **出る図は同じ形**になるので、確かめた図と書き出した図は食い違わない。
   `notes:` の字は**この 3 つに入らない**。フェンスでは TeX に字を渡さず、
   目印の色の 1 文字だけを描かせて描き上がった SVG に差し込む
   (`src/core/render/noteText.ts`)。組み方は違うが**出る字は同じ**なので、
   どちらでも日本語が出る。この道を使うのは注釈だけで、値には広げない
   (値は circuitikz のラベルに乗るので、位置も大きさも TeX が決める)。

## 運用ルール

1. **マージは fast-forward のみ**: マージコミットを作らない。作業ブランチを切って
   コミットし、`git merge --ff-only` で main に取り込み、ブランチを消す。
2. **コミットは conventional commits 形式** (`feat:` / `fix:` / `docs:` / `chore:` など)。
3. **TDD**: テストを先に書いて落とし、実装で通す。`npm run check` (型チェック +
   テスト) を通してからコミットする。カバレッジは 80% 以上を維持する。
4. **Markdown は lint を通す**:
   `npx markdownlint-cli 'README.md' 'CHANGELOG.md' 'docs/*.md' 'examples/**/*.md'`。
   設定は `.markdownlint.json` (MD013 行長・MD033 インライン HTML は無効)。
5. **サンプルは再生成してコミット**: 描画を変えたら `npm run examples` と
   `npm run docs` を実行し、`examples/out` と `docs/out` の差分も一緒に
   コミットする (`.tex` はスナップショットテストの期待値であり、
   ドキュメントが参照する図でもある)。
