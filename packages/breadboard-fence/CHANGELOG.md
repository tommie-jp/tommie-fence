## [Unreleased]

### Added

- **CLI に `check` を足した。** 何も書かずに検証とネットリストだけを出す
  (読めない行が 1 つでもあれば終了コードは 1)。図を貼る前の下読みと CI 向けで、
  LLM に書かせて直させるループでは書き出しの分だけ回転が速い。
- **1 画面の早見表** [docs/02-cheatsheet.md](docs/02-cheatsheet.md) を足した。
  プロンプトに貼る前提で全形式を圧縮してある。**載っている名前が実装から
  遅れていないかはテストで見張る** (部品名・略記・姿・注釈の語・style の項目・
  テーマ・配線の色・最上位のキーを実装側の定数と突き合わせる)。
  あわせて `docs/syntax.md` を `docs/01-syntax.md` に改名した。
- **`style: stamp: on/off`** を足した。図の右下に `breadboard-fence 0.2.0` と刻む。
  刻まない図にも SVG の根に `data-breadboard-fence` が入るので、あとから
  「どの版が描いた図か」を図そのものに聞ける。
  **この属性のぶん、既存の図の 1 行目が変わる** (絵は変わらない)。
- **読めなかったところの報告に、行の中身と印を添えるようにした。**

  ```text
  breadboard: 2 行目: 知らない部品の種類です: resistr (resistor のことですか?)
        R1: resistr a5 a10 10k
            ^^^^^^^
  ```

  頭の `breadboard:` は**どの道具が言っているか**の名札で、
  プレビューの帯でも CLI の標準エラーでも同じ文面になる。
  綴りが行の中に 2 つあるときは印を付けない (どちらでもない場所を指すより、
  指さないほうがまだ正しい)。制御文字・双方向制御・幅ゼロの文字は
  **1 文字を 1 文字に**置き換えて見せる (詰めると印の桁がずれる)。
- **お知らせ (notices) を読めなかった行と分けた。** 「読めてはいるが思ったとおりに
  出ない」もの — 使われなかった `value:` / `at:`、範囲外の数値を端へ寄せたこと、
  注釈の指し先が部品にも番地にも読めること — がこちら。
  **`style: debug: off` で伏せられるのはお知らせだけ**で、読めなかった行は
  伏せられない。`renderBreadboard()` の返り値も `errors` と `notices` に分かれる。
- **`style: debug: on/off`** を足した。
- **`#` から始まる色が YAML のコメントに食われたときのヒント。**
  `text-color: #333` は値が空で届くが、書いた本人には書いたとおりに見えるので、
  囲み方 (`"…"`) まで添えて言う。
- **CRLF を読む前に揃えるようにした** (`normalizeNewlines`)。
  行を trim して読む部品や配線は通るのに、行をそのまま使うところ
  (`- source`、報告に添える行の中身) だけが `\r` を抱えて食い違っていた。
- わざと壊した例を足した。[examples/errors/](examples/errors/) —
  読めなかったときの出方と、お知らせの出方。
  `npm run examples` の対象ではなく、**書いてある文面が実際の出力と一致するか**を
  テストで見張る (直したつもりのない親切に気づけるようにするため)。
- **`points:` を足した。** 穴番地に名前を付けると、節点を動かすときの編集が
  1 箇所で済む。番地が書ける場所すべて (部品の穴・配線の端点・注釈の指し先) で使え、
  **ネットリストにも同じ名前が出る**ので図を見ずに突き合わせられる。
  優先順はレール > 点の名前 > `N` 連番。名前に番地の形と部品 ID の重複は禁じた
  (注釈の指し先が「部品 ID か番地」の両取りなので、3 つ目の名前空間を重ねると
  解決順の説明が要る)。`points:` はフェンスのどこに書いてもよい。
- **配線を 1 行につないで書けるようにした。** `- +t5 -- b5 -- b10 red` は
  隣り合う端点ごとの区間に**パーサの中で**開かれるので、中間のモデルから先は
  今までどおり 2 点の配線しか見ない。上限は開いたあとの区間の数で数える。
  迂回ヒントを書く行だけは端点を 2 つに限る (どの区間の道順か決まらないため)。
- **`l=字` を足した。** 1 行の記法で、図に出るラベルだけを差し替える
  (マップ形式の `label:` と同じ意味)。空白は含められない。
- 例を 1 つ足した。[examples/13-points.md](examples/13-points.md) —
  点の名前・つないで書く配線・`l=`。
- **`notes:` を足した。** 図の上に印と字を重ねる。語は回路図フェンスと同じで、
  `circle` (囲む楕円) / `box` (枠、`solid` で実線) / `arrow` (指し棒) /
  `line` (直線) / `text` (字) / `source` (フェンスそのものを書き出す) の 6 つ。
  色 5 語・大きさ 5 段・寄せ 3 語・`bold` を**順不同**で添えられる。
  - 指し先は**部品 ID か穴番地**。部品を指すと部品を囲む楕円になり、
    `arrow` と `line` の端はその縁で止まる。**穴を指した端は穴そのものまで届く**
    (手前で止めると、どの穴を指しているのか分からなくなるため)。
  - **`text` だけは字を `:` の後ろに書く**。YAML のプレーンスカラーには
    コロンと空白の並びを書けず、`- text a5 "R1: …"` は黙ってマップとして
    読まれてしまうため。値の側に置けば、引用の要否を YAML が決める。
  - `source` は**行番号を添えない**。図を見た人がそのまま書き写せるのが値打ちで、
    番号が混ざると写したものが動かなくなる。板の下へはみ出すぶんは切らずに
    画布のほうを伸ばす。
  - **注釈は回路の一員ではない。** ネットにもネットリストにも部品リストにも
    数えないので、足しても導かれるネットリストは 1 行も変わらない。
- **`title:` を足した。** 図の左上に載る 1 行の題。大きさ・太さ・色は選べない
  (選べるようにすると題ではなく注釈になる。字を自由に置きたいときは `notes:` がある)。
- 例を 1 つ足した。[examples/12-notes.md](examples/12-notes.md) — 題と注釈。
- **部品を 15 種類足した。** 名前は回路図フェンス
  ([circuit-fence](https://github.com/tommie-jp/circuit-fence)) と揃えてある。
  同じノートで両方のフェンスを書くときに、語彙を覚え直さずに済むようにするため。
  - 2 本足のセンサー — `photoresistor` (CdS) / `thermistor` /
    `thermistor-ntc` / `thermistor-ptc` / `varistor`。
    サーミスタの 3 つは**同じ黒い円板で印 (`N` / `P`) だけが違う**。
    実物も形では見分けられないので、図でも印と部品リストの種類名に読ませる。
  - ダイオードの仲間 — `zener` / `schottky` / `photodiode` / `varicap` / `diac`。
    `photodiode` は砲弾型 (LED と同じ形)、`diac` は対称な素子なので**帯を描かない**。
  - ガラス封止と玉 — `reed` / `fuse` / `lamp`。リードスイッチの接点は
    **開いた状態**で描く (磁石が無い平常時と食い違わせないため)。
  - 3 本足 — `thyristor` / `triac`。`transistor` と同じ `to92` / `to220` の姿を選べる。
- **種類の略記**を足した。`r` `c` `l` `d` `ec` `ecap` `pot` `ldr` `ntc` `ptc`
  `xtal` `scr` `btn` `pushbutton` の 14 個。**読んだ直後に正式名へ畳む**ので、
  図・部品リスト・ネットリスト・エラーには正式名しか出ない
  (`R1: r a5 a10 10k` は `R1: resistor a5 a10 10k` とバイト単位で同じ図になる)。
  `ec` だけは姿まで含み、`capacitor/electrolytic` に開く。
- **書き間違いに候補を出すようにした**。`resistr` と書くと
  「resistor のことですか?」と返る。種類が 30 を超えて、
  今までのように全部並べても読めなくなったため。ピン数だけが範囲外の `dip9` には
  候補ではなく範囲 (`4〜40 の偶数`) を言う。
- 例を 1 つ足した。[examples/11-sensors.md](examples/11-sensors.md) —
  CdS とサーミスタの分圧、ダイオードの仲間、ガラス封止の部品。
- 例を 1 つ足した。[examples/09-am-radio.md](examples/09-am-radio.md) —
  バーアンテナとポリバリコンで同調し、**検波の前に 1 石で高周波を増幅する**中波ラジオ。
  `diode` の向き・`capacitor/ceramic` の姿・ボード外の機器 4 台 (アンテナ・バリコン・
  イヤホン・電池) を上下の帯に分けて置く書き方が 1 枚に入っている。

### Changed

- **README を英語と日本語の 2 本立てにした。** `README.md` が英語、
  `README.ja.md` が日本語で、題の直下に言語リンクを置く。GitHub と
  Marketplace の詳細ページに出るのは `README.md` なので、そちらを英語にした。
  **日本語が正、英語が追随**という向きを CLAUDE.md の運用ルールに書いた。
  訳すのは README 1 枚だけで、`docs/` と `examples/` は日本語のまま
  (英語側からのリンクにその旨を添えてある)。
- **文書の図をフェンスの直後に貼るようにした。** `docs/01-syntax.md` と
  `examples/*.md` のフェンスはすべて本物で、直後に**そのフェンスを描いた図**が付く。
  GitHub のようにフェンスが描画されない場所でも、書き方と出力を対で読めるようにするため。
  - **どの図にも `title: 図NN タイトル` が付いた。** 文章から「図02 を直して」と
    指せるようにするためのもの。**番号は .md ごとに 01 から**数え直す
    (通し番号にすると、1 つのファイルに図を足しただけで無関係なファイルまで振り直しになる)。
    そのぶん**既存の図はすべて題の帯だけ高くなる**。
  - **他所の図は流用しない。** `docs/01-syntax.md` は `examples/out` の図を
    borrow するのをやめ、自分のフェンスを描いた `docs/out` を持つ
    (題番号が焼き込まれているので、貼ると向こうの番号を名乗ることになる)。
  - 規約は `embeddedFigures.test.ts` (フェンスと図が 1 対 1、置き去りの出力が無い) と
    `figureNumbers.test.ts` (題がある・連番・**題が同じなら中身も同じ**) が見張る。
  - `npm run docs` を足した。`docs/01-syntax.md` の図を作り直す。
- **`docs/01-syntax.md` を構文リファレンスに絞った。** 回路ごとの実例は
  `examples/` にあり、そちらが自分の図を持つようになったので、
  重複していた「出力例 1〜5」の節を実例集へのリンクに置き換えた。
  かわりに**ボード外の機器 (`device`) の節**を足した (表からしか引けなかった)。
- `examples/README.md` を足した。目次と、図の付け方の約束。
- **読めなかったところを図の SVG から外に出した。** 帯を SVG に描き込んでいたのを
  やめ、プレビューでは図の下の HTML (`.breadboard-errors`)、
  図が 1 枚も組めないときは図の代わりのカード (`.breadboard-error-card`) にした。
  **書き出した SVG を GitHub や別のノートに貼ったときに、報告が付いてこない**のが
  いちばんの理由。ついでに字が選べるようになり、印の桁は等幅の `<pre>` が合わせる。
  - **コアを直に呼んでいる場合は受け取り方が変わる。** 図が 1 枚も組めないとき
    `svg` は空文字列になり、言うことは `errorHtml` に入る
    (それまでは `svg` にエラーカードの SVG が入っていた)。
  - CLI は図を組めなかったファイルに**空の SVG を書かない**。
- **タクトスイッチの正式名を `pushbutton` から `button` に変えた。**
  circuit-fence が `button` で公開済みで、そちらに揃えたほうが語彙が 1 つで済む。
  **`pushbutton` は略記として残す**ので、v0.2.0 で書いた図はそのまま描ける。
  変わるのは図の下の部品リストに出る種類名だけ。
- **極性を書かなかった 2 端子の向きを 1 つの規則にまとめた。**
  「極性・向きのある 2 端子は、先に書いた穴が + 側 (アノード)」。
  `led` と `diode` は最初からこの規則で描いていたのに、
  `capacitor/electrolytic` と `capacitor/tantalum` だけが
  「極性を書かないとエラー」で、同じフェンスの中に規則が 2 つある状態だった。
  **今までエラーだった書き方が通るようになるだけ**で、
  受理されていた書き方の図は変わらない。
  タンタルは印がプラス側に付くので、既定の向きも電解とは逆側になる。
- `examples/08` をエミッタ接地アンプからエミッタフォロワに差し替えた
  (`08-common-emitter.md` → [08-emitter-follower.md](examples/08-emitter-follower.md))。
  同じ 1 石でも**電圧を増やす段と電流だけを増やす段**が並ぶより、
  バッファ段を見せて次の例 (ラジオの高周波増幅) へ渡すほうが読む順に合う。
- ラジオを 09 に入れたので、B-H 測定回路を
  `09-bh-ad2.md` → [10-bh-ad2.md](examples/10-bh-ad2.md) に繰り下げた
  (図の中身は変わっていない)。

### Fixed

- **1 行に端点を並べた配線が上限を素通りしていた。** 上限を「行の数」で見ていたので、
  つないで書いた 1 行が何本にでも開けた。端点 2 万個の 1 行 (137 KB) で
  **描画に 19.6 秒**かかり、同期処理なので拡張ホストが止まる。
  開いたあとの区間の数で頭を打たせるようにした (16ms)。
- **`l=ラベル` と値の両方を書くとラベルが黙って消えていた。**
  図に出るキャプションは値を先に見る (部品リストの値は図と同じ字である約束なので、
  ラベルを勝たせるわけにいかない)。図はそのままに、お知らせで理由を言う。
  マップ形式の `label` + `value` も同じ。
- **点の名前にレールの名前 (`-t` `-b`) が付けられた。** ネットリストに
  **同じ名前のネットが 2 つ**出て、突き合わせがそこで成立しなくなる。
  番地の形と同じ理由で禁じた (`+t` は `+` が名前に使えないので元から通らない)。
- **略記で書いた姿のエラーで、印が行の別の語に付いていた。**
  `C1: c/foo …` の報告が畳んだあとの `capacitor/foo` を探していたため。
  書かれたままの綴りを覚えて指すようにした。
- **機器 (`device`) の `value:` を黙って捨てていた**。`schema.ts` は受理するのに
  図のどこにも出ない (箱に出るのは `label ?? ID`) ので、書いた人には何も伝わらなかった。
  行番号つきで「機器 (device) に value は使いません」と報告するようにした。
  **機器そのものは今までどおり描く**。落とすのは値だけ。
- **機器以外の `at:` も同じく黙って捨てていた**。`at` を読むのは機器を上下の帯に
  振り分けるところだけで、板に挿す部品の位置は `holes` が決める。上と同じ形で
  行番号つきに変えた (部品は今までどおり描き、落とすのは `at` だけ)。
- **図の中のキャプションが板からはみ出しても切れていなかった**。`limits.ts` が
  切っているのは文字数 (60) で幅ではなく、全角 60 文字は既定のテーマで 750px ある。
  half サイズの画布 (664px) には最初から入らないので、板の端の部品に長い値を付けると
  **viewBox の外へ出て黙って消えていた** (実測で右へ 293px)。部品リストと同じ
  `…` で切るようにした。幅の見積もりは `render/textFit.ts` に切り出して共有する。
- **部品リストの全角判定が BMP 止まりで、サロゲートペアの文字を半角に数えていた**。
  絵文字と CJK 拡張 B 以降が幅の半分として見積もられ、`fit()` が切らずに
  板からはみ出していた。全角の範囲に BMP の外を足して、広めに見積もる側へ寄せた
  (多く数えれば早めに切るだけだが、少なく数えるとはみ出す)。
  **既存の図は 1 バイトも変わらない** (BMP の日本語はもともと全角に数えていた)。

- `.vsix` に入っていた examples の PNG (1.1 MB) を外した。**993 KB → 114 KB**。
  `.vscodeignore` が `examples/out/*.svg` だけを除いて PNG を書き忘れていた。
  拡張は実行時に SVG を組み立てるので読むことは無く、README の図は vsce が
  GitHub の絶対 URL に書き換えるため、詳細ページの見え方も変わらない。
- `examples/*.md` に読む順の番号を付けた (`led.md` → `01-led.md`)。
  最小の回路から実験回路へ、上から順に難しくなる。`examples/out` の
  書き出し名も追従する (図の中身は 1 バイトも変わっていない)。

## [0.2.0] - 2026-08-25

部品が一気に増えた版。既定で図の下に部品リストが出るようになったので、
**これまでの図は部品リストのぶんだけ高くなる** (`parts-list: none` で戻せる)。

### Added

- 部品の姿を `種類/姿` の 1 トークンで選べるようにした。同じ役割・同じ極性で、
  実物のかたちだけが違うものを描き分ける。`capacitor/ceramic` `capacitor/film`
  `capacitor/electrolytic` `capacitor/tantalum` / `led/3mm` `led/5mm` /
  `transistor/to92` `transistor/to220`。**姿を書かないときの絵は変わらない**。
- 極性の印を姿ごとに描き分ける。**電解の帯はマイナス側、タンタルの印はプラス側**に付く。
  取り違えると部品を壊すので、形 (缶 / 粒) からも見分けられるようにした。
- 極性つきの 2 本足は、ピン名が片側だけでもよくなった
  (`capacitor/electrolytic a5(+) a8`)。2 本足なので反対側は決まる。
- Raspberry Pi Pico シリーズ (`pico` / `pico-w` / `pico2` / `pico2-w`)。
  ピン 1 の穴だけを書くと、幅 0.7 インチのピン 2 列が上下ブロックの同じ位置の行
  (`h` と `c` など) に落ちる。**ピン名は実物のピンアウトの印字そのまま**
  (`MCU.GP15` `MCU.3V3`)。名前が重なる GND はピン番号を付けて `GND3` `GND8` … と呼ぶ。
- タクトスイッチ (`pushbutton`)。溝をまたぐ 4 本足で、**同じ側の 2 本が
  押していなくてもつながっている**ことを図とネットリストの両方に出す。
- 半固定抵抗 (`potentiometer`) とスライドスイッチ (`slide-switch`)。
  つまみの位置と倒れている向きは、図では示さない (状態で変わるものは描かない)。
- 2 本足の部品を 4 つ追加: `diode` (カソード帯) / `buzzer` / `crystal` / `inductor`。
- 1 列ヘッダ (`sipN`)。`pins:` で足に名前を付けられるので、ヘッダ 1 列の
  モジュール (OLED や測距センサ) をこれで描ける。
- 配線のピン名を書き間違えたとき、同じ書き出しのピンを候補として添える。
- 図の下の部品リスト。`parts:` に書いた部品が ID・種類・値の順に 1 行ずつ並ぶ。
  **既定で出る**ので、これまでの図は部品リストのぶんだけ高くなる。
  `parts-list: none` で消せば従来と同じ図に戻る。
- `board:` のマップ形式。レールの並び (`rails`)・行ラベルの大小 (`letters`)・
  列番号の間引き (`numbers`) を、手元のボードの印字に合わせて選べる。
  番地系は印字に依らず共通で、既定値のときの出力は従来と同一。
- 番地は大小どちらでも書けるようにした (`A5` == `a5`、`+T5` == `+t5`)。
