# 図を掴んで動かす

図を見ながら部品や穴を掴んで動かし、フェンスの番地を書き換える操作。
**位置を穴番地で書く**フェンスなので、「動かす」は行の中の綴りを
差し替えるだけで済む。

**操作は 3 つのフェンスで同じ** (KiCad 流。鍵・手つき・画面の配置)。
共通の操作は fence-kit の
[docs/01-図を掴んで動かす.md](../../fence-kit/docs/01-図を掴んで動かす.md)
にまとめてある。ここに書くのは **breadboard での違い**だけ。

## 2 つの入口

| 開き方 | どうなるか |
| --- | --- |
| タブの頭の一覧から `breadboard Editor` | `.md` のタブそのものが図のエディタになる |
| `Breadboard Fence: 図を掴んで動かす (マップ)` | エディタの横にマップを開く |

## 掴むのは図そのもの

マップは**別に描いた升目ではなく、図そのもの**。穴の上に透明な当たり判定が
重なっているだけなので、見えている絵と掴む場所が食い違わない。

## 置く (この板での穴の並べ方)

`A` で種類を選ぶと、押した穴を 1 つ送るだけで**残りの穴はこちらが並べる**。

| 種類 | 押した穴から |
| --- | --- |
| 2 本足 | 同じ行の右へ、既定の間隔 (抵抗 5 穴、LED 1 穴、ほか 3 穴)。ドラッグすれば間隔を選べる |
| 3 本足 (トランジスタなど) | 同じ行の右へ 2 穴 (`c5` → `c5 c6 c7`) |
| タクトスイッチ | `@ 穴` (足の位置はパッケージが決める) |

- **レールには置けない** (`+t5` など)。行が丸ごと 1 本の電位なので、足が全部
  同じ節点に入った図が黙って出る。ゴーストが赤くなって理由が出る
- **右へ入らなければ断る** (左へ折り返さない — 押した場所で向きが変わる規則に
  しない)。「右へ 2 穴ぶん要ります」と言う
- 足の印 (`(B)` `(C)` `(E)`) は書かない。ピン配列は型番の話なので、書く人が付ける
- 名前は**接頭辞ごとに最小の未使用番号** (`D1` が LED なら次のダイオードは `D2`)

## 回す・反転する

`R` で時計回り、`Shift+R` で反時計回り、`X` で反転。**掴んだ物によって
行の直り方が変わる**が、押す側から見ればどちらも 1 つの操作。ゴーストにも効く。

**足を並べて書く部品 (2 本足・3 本足)** — 穴の番地が動く。

- **アンカー (先に書いた足) は動かない。** 動かすと「回す」が「移動」になる
- 反転は**足の並びの入れ替え**。極性の印 (`b12(A)`) も一緒に入れ替わる —
  番地だけ入れ替えると、アノードが反対の穴へ移る別の意味の行になる。
  3 本足なら両端が入れ替わり、真ん中はその場に残る
- **レールに挿さった足は回せない** (行が極性そのものなので、行を足し引きしても
  意味を持たない)

**アンカー 1 つで置く形 (DIP / ヘッダ / マイコンボード)** — 向きの語と行が直る。

- `R` は**半周ぶん**回す (`r180` を出し入れする)。この板で 90 度に相当する
  置き方は実物に無いので、4 分の 1 ずつは回らない →
  [部品の向き](01-syntax.md#部品の向き-r180)
- `X` は**アンカーを溝の向こうの行へ移す** (`@ e5` → `@ f5`)。
  それが実物を裏返した形そのものなので、`mirror` の語は置いていない
- **タクトスイッチは回せない。** 対称なので、回しても同じ穴どうしがつながる
- **1 列ヘッダは裏返せない。** 1 列に並ぶので、裏返しても同じ穴に同じ順で挿さる

## 名前・種類・値を直す

部品を選ぶと左に欄が出る。`Enter` か欄を離れたときに行へ当たる。

- **名前**を変えると、鍵と**その部品を指す注釈**が一緒に変わる
- **種類**は置く前に確かめる (知らない種類は断る)
- **値**とラベルは `#` や YAML の記号を通さない — 行の形が壊れて値が黙って
  消えるため

## 部品を動かす

**最初の穴がアンカー**で、部品は形を保ったまま平行移動する。

```yaml
R1: resistor a5 a10 330
```

`R1` を `c5` へ動かすと `resistor c5 c10` になる。値も極性の印
(`b12(A)` の `(A)`) も名前も触らない。

板の外へ出る移動は断る (行は `a`〜`j`、列はボードの穴数まで)。
**レールは行そのものが極性**なので (`+t5` の 2 つ下は `-t5` ではない)、
レールが絡む移動は列だけが動く。

## 節点を動かす

その穴に来ているものを丸ごと運ぶので、**接続は保たれる**。

`points:` で名前が付いていれば、直すのは**普通はその行き先の 1 行だけ**。

```yaml
points:
  vin: a5
parts:
  R1: resistor vin a10 330
wires:
  - +t5 -- vin red
```

`vin` の節点を `c5` へ動かすと `vin: c5` の 1 行だけが変わり、`R1` も配線も
綴りを変えずに付いてくる。**これが `points:` の存在理由**そのもの。
同じ穴を生の綴りでも書いていたら、そこも一緒に運ぶ — 置いていくと接続が
切れて、「丸ごと運ぶ」の約束が破れる。

**縮退は断る。** 寄せた先に自分のもう一方の足がある部品は長さ 0 になり、
図から消えてしまう。その組み合わせは動かす前に名指して断る。

## 接続が変わったら教える

**動かす前に止めない。** 移動の前後でネットリストを比べ、**離れた接続と、
つながった接続を動かしたあとに**状態行へ並べる。

**同じ列の 5 穴はつながっている**ので、`a10` から `c10` へ寄っても導通は
変わらない — そのときは何も言わない (言うと嘘になる)。溝をまたげば言う。

`points:` で名前を付けた穴も**接続の相手として数える**。部品が 1 つしか
来ていないネットでも、名前から離れたことは知らせる値打ちがあるため。

## いまできないこと

**タクトスイッチを回す・1 列ヘッダを裏返す**のはできない (上の節)。
押すと理由が返る (黙って何も起きない道具にはしない)。

**配線を折る綴りが無い** ので、`Shift` を押しても配線はまっすぐのまま
(案内にも出ない)。

**DIP / SIP / マイコンボードはパレットに出ない** (手で 1 行書けば、あとは
マップで動かせる・回せる)。

**フロー形式 (`parts: {R1: …}`) の行は消せない・足せない。** その書き方では
行が 1 つのものに対応しないので、行ごと消すと鍵まで消える。動かすほうは
今までどおり効く。

## 書き換え方

**YAML を組み直さない。** 行の中の穴の綴りだけを差し替えるので、
手書きのコメント・整形・並び順がそのまま残る。
